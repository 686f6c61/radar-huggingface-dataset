## Arquitectura y entrenamiento

La arquitectura es de tipo MoE, según la etiqueta `qwen3_5_moe`. Esto implica que el modelo utiliza múltiples expertos y activa solo un subconjunto de ellos por token, lo que reduce el coste computacional en inferencia en comparación con un modelo denso del mismo tamaño total. Sin embargo, no se dispone de detalles sobre el número de expertos, la dimensión del espacio latente ni el mecanismo de enrutamiento.

El modelo es el resultado de un proceso de fusión de LoRA sobre el checkpoint `kevin954/Affine-5dfqbbh8ev-sft`. La etiqueta `affine-h1-merged-salvage` sugiere que se trata de un "salvamento" de un checkpoint fusionado, posiblemente para preservar el estado del modelo en un punto intermedio. No hay información sobre el conjunto de datos de entrenamiento, el número de tokens procesados ni si se aplicaron técnicas como RLHF o DPO. Tampoco se especifica si el modelo base fue entrenado desde cero o es un fine-tuning de Qwen3.5.
