# siddharthmb/2026.TA.gemma2_2b_tc8192_decb_l1w0.001_tarbb_lb2.0_ln1_dr10000_lr8e-04_bs4_sl14763212

## Resumen

Este repositorio contiene un adaptador transcoder disperso (sparse transcoder adapter) entrenado en modo bridging sobre google/gemma-2-2b. No es un modelo de lenguaje independiente: es un artefacto de interpretabilidad y adaptacion dispersa que se acopla a un modelo Gemma 2 de 2B parametros para sustituir las MLP por una rama de transcoders de 8192 caracteristicas. El checkpoint ocupa 7,2 GB y declara 3.596.081.920 parametros en safetensors, frente al orden de 2,6 mil millones del modelo base, de modo que la rama de transcoders anade aproximadamente 1.000 millones de parametros.

El entrenamiento se realizo sobre science-of-finetuning/fineweb-1m-sample y siddharthmb/2026.transcoder-adapters.lmsys-chat-1m-splits, con una unica epoca, learning rate 8e-04, batch size 4, perdida KL y una combinacion de terminos lambda_adapt 1.0, lambda_bridge 2.0 y lambda_nmse 1. El modo bridging implica que el adaptador se entrena para reproducir el comportamiento del modelo de referencia (google/gemma-2-2b-it) manteniendo el backbone objetivo, lo que permite alternar entre el modelo hibrido y el adaptador disperso mediante `set_transcoders_enabled(False)`.

Su relevancia es fundamentalmente de investigacion: sirve para analizar circuitos internos mediante grafos de atribucion con GemmaScope, para hacer steering de caracteristicas individuales por su identificador cantor, y para estudiar adaptacion dispersa con interpretabilidad nativa. El repositorio tiene 3 descargas y 0 likes, no declara licencia ni idiomas, y requiere las clases de modelo propias del proyecto (no se carga con `AutoModelForCausalLM`).

## Arquitectura y entrenamiento

La base es Gemma 2, un transformer decoder-only con atencion alternada (ventana deslizante local y atencion global), normalizacion RMSNorm, activaciones GeGLU y soft-capping de logits. Sobre esa base, este checkpoint sustituye la ruta de las MLP por una rama de transcoders dispersos: representaciones densas de 8192 caracteristicas con sesgo de decodificador y regularizacion L1 de 0.001, orientadas a obtener activaciones dispersas y mas interpretables. El tokenizador empleado es el de google/gemma-2-2b-it y el modelo de referencia para la senal de supervision es tambien google/gemma-2-2b-it.

El regimen de entrenamiento es bridging con backbone objetivo: una epoca, batch size 4, learning rate 8e-04, warmup ratio 0.05, perdida de tipo KL, lambda_adapt 1.0, lambda_bridge 2.0, lambda_nmse 1 y n_cutoffs 1. No se documenta el numero total de tokens procesados, la composicion exacta del dataset ni si hubo fases de RLHF o DPO; la informacion disponible solo identifica las dos fuentes de datos de entrenamiento y el enlace a la ejecucion de W&B. La innovacion tecnica destacable es la combinacion de adaptacion dispersa con interpretabilidad: el adaptador es inspeccionable mediante grafos de atribucion y permite steering por caracteristica.

## Casos de uso

- Analisis de circuitos internos: construir grafos de atribucion con `analysis.attribution.graphs.build_graphs` para identificar que caracteristicas del transcoder contribuyen a una prediccion concreta, usando el adaptador como sustituto trazable de las MLP.
- Steering controlado en experimentos: activar o desactivar caracteristicas por cantor id para observar cambios dirigidos en la generacion, por ejemplo en estudios de sesgo o de factualidad.
- Investigacion en adaptacion dispersa: comparar este checkpoint con las otras variantes de la coleccion "2026 Transcoder Adapters", que difieren en learning rate e hiperparametros, para aislar el efecto de cada termino de la perdida.
- Validacion de metodos de bridging: evaluar si un adaptador entrenado con lambda_bridge 2.0 reproduce fielmente el comportamiento de google/gemma-2-2b-it conservando el backbone objetivo.
- Docencia de interpretabilidad: el modelo (2B de base, 7,2 GB en disco) es lo bastante pequeno para ejecutar demostraciones de transcoders y atribucion en una sola GPU, algo inviable con modelos de escala mayor.
- Extraccion de caracteristicas para pipelines de analisis: usar las activaciones dispersas de 8192 dimensiones como representacion intermedia en estudios de probing o de deteccion de conceptos.
- Comparacion entre supervisores: dado que el tokenizador y el modelo de referencia son gemma-2-2b-it, sirve para estudiar como se comporta un transcoder cuando la senal de KL proviene de un modelo ajustado a instrucciones en lugar del modelo base.

## Limitaciones y advertencias

- Ausencia total de evaluacion: no hay benchmarks, y la model card no reporta ninguna metrica de calidad, fidelidad frente al modelo de referencia ni grado de dispersión efectiva alcanzado.
- Uso previsto restringido: es un artefacto de investigacion con 3 descargas; no debe tratarse como un modelo de produccion para generacion de texto.
- Dependencia de codigo externo: la carga requiere las clases del repositorio https://github.com/Sid-MB/transcoder-adapters; `AutoModelForCausalLM` y el flujo estandar de transformers no bastan. La carga desde la version publicada del paquete puede quedar desincronizada respecto al commit usado en el entrenamiento.
- Licencia del adaptador no disponible: no se puede asumir permiso de uso comercial. El modelo base esta sujeto a los terminos de uso de Gemma, que imponen obligaciones adicionales de atribucion y uso aceptable.
- Idiomas no declarados: se desconoce la cobertura multilingue, y cualquier comportamiento linguistico proviene del modelo base, predominantemente entrenado en ingles.
- Riesgo de alucinacion y sesgos: no evaluado especificamente para este adaptador; hereda las limitaciones de google/gemma-2-2b, incluidos sesgos de genero, origen y idioma, y la posibilidad de generar contenido incorrecto con seguridad alta.
- Ventana de contexto limitada: 8192 tokens como maximo heredado del base, insuficiente para tareas de contexto largo.
- Sustitucion de las MLP: al reemplazar las MLP por transcoders dispersos, la calidad puede degradarse de forma no cuantificada respecto al modelo original; la propia model card ofrece la ruta `set_transcoders_enabled(False)` para recuperar el comportamiento hibrido.
- Reproducibilidad incompleta: faltan datos de tokens de entrenamiento, composicion exacta del dataset y semilla; los fragmentos `dr10000` y `sl14763212` del nombre no estan documentados.
- Ausencia de garantias de estabilidad: al ser un entrenamiento de una sola epoca con batch size 4, la varianza entre ejecuciones puede ser alta, como sugiere la existencia de variantes del mismo autor con learning rates distintos (8e-04 frente a 3e-04).
