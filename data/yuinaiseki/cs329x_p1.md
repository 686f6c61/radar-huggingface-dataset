# yuinaiseki/CS329X_P1

## Resumen

CS329X_P1 es un adaptador LoRA entrenado mediante DPO (Direct Preference Optimization) sobre el modelo base meta-llama/Llama-3.2-1B-Instruct, publicado por el usuario yuinaiseki en HuggingFace. Por los identificadores del repositorio (CS329X hace referencia al curso de la Universidad de Stanford sobre NLP centrado en humanos) y por la ausencia de documentación, se trata con alta probabilidad de un artefacto académico o de un experimento de fine-tuning más que de un modelo destinado a producción.

El modelo hereda la arquitectura del transformer decoder-only de Llama 3.2, con aproximadamente 1.230 millones de parámetros y una ventana de contexto de hasta 128.000 tokens en su forma base. El entrenamiento mediante DPO y LoRA sugiere un ajuste de preferencias sobre el modelo instruct ya existente, orientado a alinear las respuestas generadas con pares de preferencia, sin reentrenar todos los pesos.

Su relevancia es limitada en términos prácticos: no acumula descargas ni interacciones, el repositorio no incluye una model card descriptiva y el tamaño publicado es de 0,0 GB (compatible con un adaptador LoRA de pequeño tamaño). Resulta útil como referencia para quien quiera reproducir un pipeline de DPO+LoRA sobre un modelo pequeño, pero no aporta información verificable sobre el dataset de preferencias, hiperparámetros o resultados.

## Arquitectura y entrenamiento

El modelo no publica información sobre su proceso de entrenamiento. A partir de los tags (`dpo`, `lora`) y del `base_model` declarado, se deduce que se trata de un adaptador LoRA (Low-Rank Adaptation) añadido sobre los pesos congelados de meta-llama/Llama-3.2-1B-Instruct, y posteriormente ajustado mediante DPO sobre un conjunto de pares de preferencia. El número de tokens de entrenamiento, la composición del dataset de preferencias, la configuración del LoRA (rango, alpha, módulos objetivo) y los hiperparámetros del DPO no están disponibles.

La arquitectura subyacente es la de Llama 3.2 1B: un transformer decoder-only con atención por ventanas deslizantes y atención global combinadas, 16 capas, dimensión de modelo de 2.048, GQA (Grouped Query Attention) y tokenizador BPE con un vocabulario de 128.000 entradas. El modelo base incorpora además soporte de tool calling y de plantillas de chat. No se documenta ninguna innovación técnica adicional en este adaptador más allá de la propia aplicación de DPO sobre LoRA.

## Capacidades

- Generación de texto conversacional en inglés, heredada del modelo instruct base.
- Alineación de respuestas mediante DPO, presumiblemente orientada a mejorar la preferencia de las salidas frente al modelo base.
- Capacidad de razonamiento básico y generación de código limitada, coherente con un modelo de 1B parámetros.
- Soporte de tool calling y function calling en la forma base de Llama-3.2-1B-Instruct (no confirmado tras el ajuste DPO+LoRA).
- Capacidades multilingües reducidas: el repositorio solo declara inglés, aunque el modelo base soporta oficialmente ocho idiomas.
- No se documentan modos especiales (thinking mode, visión, audio, decodificación especulativa específica).

## Casos de uso

- Experimentación académica con pipelines de DPO: el modelo sirve como ejemplo reproducible de adaptación por preferencias sobre un modelo pequeño, útil en cursos o trabajos de investigación sobre alineación.
- Fine-tuning sobre dominio específico con recursos limitados: al ser un adaptador LoRA sobre 1B parámetros, puede entrenarse en una única GPU consumer, lo que lo hace adecuado para prototipos de bajo coste.
- Generación de texto ligera en inglés: despliegue en dispositivos con pocos recursos para tareas de respuesta corta, resumen o reescritura, siempre que la calidad exigida sea moderada.
- Investigación sobre degradación de capacidades tras DPO: permite comparar sus salidas con las del modelo base para estudiar cómo el ajuste por preferencias afecta a un modelo de 1B parámetros.
- Prototipado de chatbots conversacionales: su formato instruct y su licencia Llama permiten integrarlo en demos internas, aunque la falta de evaluación desaconseja producción.
- Base para posteriores ajustes: puede usarse como punto de partida para nuevos adaptadores LoRA especializados sobre el mismo modelo base de Meta.

## Requisitos de hardware

- VRAM estimada para inferencia (adaptador + modelo base Llama-3.2-1B): aproximadamente 2,5 GB en FP16, ~1,5 GB en cuantización 8-bit y ~1 GB en 4-bit.
- GPU recomendadas: cualquier GPU con al menos 4 GB de VRAM para FP16, como RTX 3050, RTX 4060, RTX 4090, A10, L4. Para despliegues conjuntos con otros adaptadores, se recomienda A100 o H100 si se sirven varias variantes.
- Compatibilidad con GPU consumer: sí, cabe holgadamente en cualquier GPU consumer moderna, incluida una RTX 3060 de 12 GB o incluso una GTX 1650 de 4 GB en 4-bit.
- Opciones de despliegue: al ser un adaptador LoRA sobre Llama 3.2, puede servirse con PEFT + Transformers, vLLM o TGI cargando el adaptador sobre el modelo base, o exportarse a GGUF para llama.cpp y Ollama.
- Latencia y throughput estimados: no disponibles; para un modelo de 1B parámetros en GPU moderna se espera en el rango de decenas a cientos de tokens por segundo, pero no hay mediciones publicadas para este adaptador.

## Limitaciones y advertencias

- No hay model card descriptiva: se desconoce el dataset de preferencias, los hiperparámetros y el proceso de evaluación, lo que impide reproducir el entrenamiento.

- Tamaño del repositorio de 0,0 GB: conviene verificar que los archivos del adaptador estén efectivamente presentes antes de intentar cargarlo.
