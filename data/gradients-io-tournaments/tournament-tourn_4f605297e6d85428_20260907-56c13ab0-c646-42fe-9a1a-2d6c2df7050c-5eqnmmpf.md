## Resumen

El modelo `tournament-tourn_4f605297e6d85428_20260907-56c13ab0-c646-42fe-9a1a-2d6c2df7050c-5EqnMmpf` es un adaptador LoRA generado en el marco de un torneo de entrenamiento descentralizado de la plataforma Gradients.io (Subnet 56). Se trata de un fine-tuning supervisado (SFT) sobre el modelo base `unsloth/Meta-Llama-3.1-8B-Instruct`, publicado por la organizacion `gradients-io-tournaments`. El repositorio tiene un tamano de 1,4 GB, coherente con un adaptador PEFT/LoRA para un modelo de 8B, y fue creado el 8 de septiembre de 2026.

Al tratarse de un adaptador LoRA, no es un modelo autonomo: requiere cargar el modelo base y fusionar o aplicar los pesos del adaptador para su uso. La model card del autor no aporta informacion funcional, tecnica ni de datos de entrenamiento, por lo que las capacidades concretas del adaptador no estan documentadas mas alla de lo que se puede inferir del modelo base.

## Arquitectura y entrenamiento

El modelo es un adaptador LoRA (Low-Rank Adaptation) construido sobre `unsloth/Meta-Llama-3.1-8B-Instruct`. La arquitectura subyacente es la de Llama 3.1 8B, un transformer decoder-only con attention por grupos de consultas (GQA), normalizacion RMSNorm y activaciones SwiGLU. Los pesos del adaptador se almacenan en formato safetensors y se aplican mediante la libreria PEFT 0.18.1, tal y como indica la etiqueta de framework del repositorio.

El proceso de entrenamiento se realizo con Supervised Fine-Tuning (SFT) usando la libreria TRL, segun las etiquetas del modelo (`sft`, `transformers`, `trl`). No se han publicado datos sobre el conjunto de entrenamiento, el numero de tokens, el regimen de precision (fp16, bf16, etc.) ni si hubo etapas de RLHF o DPO. La etiqueta `base_model:adapter:/cache/models/f99f8d94fa0fd6f3` sugiere que el entrenamiento partio de un adaptador previo almacenado en cache, pero no se aportan detalles adicionales. Tampoco se ha documentado innovacion tecnica alguna mas alla del uso de LoRA como tecnica de fine-tuning eficiente.

## Requisitos de hardware

Dado que el repositorio contiene un adaptador LoRA y no un modelo completo, los requisitos de hardware dependen del modelo base que se utilice. Las estimaciones siguientes se basan en el modelo base Llama 3.1 8B, no en el adaptador en si:

- VRAM estimada para inferencia: el modelo Llama 3.1 8B en FP16 requiere aproximadamente 16 GB de VRAM. Con cuantizacion de 4 bits se puede reducir a 6-8 GB. El adaptador LoRA anade un consumo adicional minimo.
- GPU recomendadas: para FP16 completo se recomienda una GPU de 24 GB (RTX 4090, A10G, A100 40GB). Para cuantizacion de 4 bits son suficientes GPUs con 8-12 GB, como RTX 4070 o RTX 4060 Ti.
- Compatibilidad con consumer GPU: si, con cuantizacion de 4 bits el modelo base cabe en GPUs de gama media, aunque el adaptador requiere cargar el modelo base completo.
- Opciones de despliegue: llama.cpp, Ollama, vLLM, TGI, Transformers con PEFT. El adaptador puede fusionarse con el modelo base mediante `peft.merge_and_unload()`.
- Latencia y throughput: no disponible. No se han publicado mediciones de rendimiento para este adaptador.
