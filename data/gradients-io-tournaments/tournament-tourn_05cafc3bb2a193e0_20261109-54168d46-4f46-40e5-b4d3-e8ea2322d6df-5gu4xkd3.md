# gradients-io-tournaments/tournament-tourn_05cafc3bb2a193e0_20261109-54168d46-4f46-40e5-b4d3-e8ea2322d6df-5GU4Xkd3

## Resumen

Este repositorio contiene un adaptador LoRA entrenado mediante DPO (Direct Preference Optimization) sobre el modelo base `unsloth/codegemma-7b`, un derivado de CodeGemma-7B optimizado por Unsloth. El adaptador se distribuye como un artefacto PEFT independiente (1,6 GB en safetensors), no como un modelo completo, por lo que requiere cargar el modelo base y aplicar el adaptador encima para su uso. El identificador del repositorio sugiere que se trata de un resultado de un torneo de entrenamiento alojado en la plataforma gradients-io-tournaments, con fecha de creación el 10 de noviembre de 2026.

El modelo base CodeGemma-7B es un transformer decoder-only de 7 mil millones de parámetros desarrollado por Google, especializado en generación de código y completado de código, con una longitud de contexto de 8.192 tokens en su variante de instrucciones. El adaptador añade un ajuste fino por preferencias (DPO) con rango LoRA, lo que en principio alinea las respuestas del modelo hacia preferencias humanas o de tarea específicas, aunque la model card no documenta qué dataset de preferencias se utilizó ni qué objetivo concreto se persiguió.

La relevancia de esta ficha es limitada pero real: se trata de un artefacto experimental de un torneo, sin documentación sustantiva, sin licencia declarada y sin benchmarks publicados. Resulta útil como ejemplo de pipeline PEFT+DPO sobre CodeGemma y como punto de partida para quien quiera reproducir o inspeccionar el adaptador, pero no es un modelo listo para producción sin una evaluación adicional exhaustiva.

## Arquitectura y entrenamiento

El adaptador se construye sobre CodeGemma-7B, un transformer decoder-only con atención multi-cabeza estándar, 28 capas y dimensión oculta de 3.072 (arquitectura Gemma). CodeGemma se preentrenó con 500 mil millones de tokens adicionales sobre Gemma, con un énfasis marcado en código (repositorios públicos, lenguajes de programación y datos de razonamiento matemático). La variante de instrucciones incorpora ajuste supervisado y RLHF, y su contexto nativo es de 8.192 tokens.

Sobre ese base, este repositorio aplica un adaptador LoRA (Low-Rank Adaptation) entrenado con DPO mediante la librería TRL, según los tags del repositorio (`dpo`, `lora`, `trl`, `peft`). El entrenamiento DPO optimiza el modelo para preferir respuestas etiquetadas como mejores frente a peores, sin necesidad de un modelo de recompensa explícito. No se documenta el dataset de preferencias, el rango LoRA, el alpha, la tasa de aprendizaje, el número de pasos ni el hardware utilizado. La versión de PEFT declarada es 0.19.1. No hay innovaciones técnicas destacables más allá del uso de DPO sobre un adaptador de bajo rango.

## Capacidades

- Generación de texto y código: hereda del base CodeGemma-7B la capacidad de completar código, generar funciones y explicar fragmentos de código en varios lenguajes de programación.
- Razonamiento matemático básico: CodeGemma se entrenó con datos matemáticos, por lo que conserva cierta competencia en problemas aritméticos y algebraicos sencillos.
- Relleno de código (fill-in-the-middle): el base CodeGemma-7B incluye una variante específica para FIM; no se confirma que el adaptador preserve esta capacidad.
- Ajuste por preferencias: el DPO puede haber alineado el estilo de respuesta hacia formatos concretos, aunque se desconoce cuáles.
- Tool calling / function calling: no documentado; CodeGemma no incluye un formato nativo de tool calling, por lo que requeriría prompting estructurado.
- Agentes y razonamiento multi-paso: no documentado ni evaluado.
- Capacidades multilingües: no documentadas; el base está orientado a inglés y código.
- Modo thinking, visión o audio: no disponibles.

## Casos de uso

- Experimentación con pipelines DPO: el adaptador sirve para estudiar cómo DPO modifica el comportamiento de CodeGemma-7B en tareas de código, comparando respuestas con y sin adaptador en un entorno controlado.
- Reproducción de torneos de entrenamiento: útil para participantes o investigadores que quieran inspeccionar los hiperparámetros efectivos del adaptador (rango, capas afectadas) y replicar el proceso.
- Generación de código asistida en entornos de investigación: se puede cargar con PEFT y transformers para autocompletar funciones en notebooks o scripts, siempre con revisión humana.
- Evaluación de alineación en dominios de código: permite medir si el DPO mejora la preferencia de estilo (por ejemplo, comentarios, manejo de errores) sin cambiar la corrección funcional.
- Base para un segundo ajuste fino: al ser un adaptador LoRA ligero, se puede combinar con otros adaptadores o continuar el entrenamiento con un dataset propio de preferencias.
- Docencia y formación: ejemplo práctico de cómo se aplica DPO sobre un modelo de código con TRL y PEFT, útil en cursos de ajuste fino.

## Requisitos de hardware

- VRAM estimada para inferencia: el modelo base CodeGemma-7B en fp16 requiere aproximadamente 14-16 GB de VRAM; en int8, unos 8-9 GB; en int4 (GGUF/AWQ), unos 5-6 GB. El adaptador LoRA añade una sobrecarga mínima (menos de 1 GB en fp16).
- GPU recomendadas: A100 40 GB, H100 80 GB o L40S para fp16 con contexto completo; RTX 4090 (24 GB) para fp16 con contexto moderado; RTX 3090/4080 (16 GB) para int8; RTX 3060 12 GB o RTX 4060 Ti 16 GB para int4.
- Cabe en GPU de consumo: sí, en cuantización int4 o int8 en tarjetas con 8-16 GB, y en fp16 en RTX 4090.
- Opciones de despliegue: transformers + PEFT (carga del adaptador), vLLM (soporte de adaptadores LoRA), llama.cpp/Ollama (requiere fusionar el adaptador con el base y convertir a GGUF), TGI (soporte de adaptadores LoRA).
- Latencia y throughput estimados: no disponibles; dependerán del hardware y de la cuantización. Como referencia, CodeGemma-7B en una A100 genera del orden de 40-60 tokens/s en fp16 con batch pequeño, pero no hay mediciones específicas de este adaptador.

## Limitaciones y advertencias

- Model card prácticamente vacía: no se documentan datos de entrenamiento, hiperparámetros, evaluación ni uso previsto; cualquier uso en producción requiere evaluación propia.
- Licencia no declarada: no se puede asumir uso comercial; además, el modelo base CodeGemma está sujeto a los Gemma Terms of Use, que imponen restricciones adicionales.
- Riesgo de alucinación: como todo modelo de código, puede generar APIs inexistentes, imports incorrectos o código que compila pero falla en tiempo de ejecución.
- Sesgos: no evaluados; CodeGemma se entrenó con datos web y de repositorios, con los sesgos asociados (lenguajes sobrerrepresentados, estilos de código concretos).
- Limitaciones de idioma: el base está orientado a inglés y código; el soporte de castellano es limitado y no se ha evaluado en el adaptador.
- Contexto limitado a 8.192 tokens: insuficiente para repositorios grandes o conversaciones muy largas sin técnicas de recuperación.
- Artefacto de torneo: sin mantenimiento, sin issues, sin comunidad; 0 descargas y 0 likes en el momento de la ficha.
- DPO sin evaluación: no hay evidencia de que el ajuste por preferencias mejore la corrección del código; podría haber degradado capacidades del base.
