# Jordine/rlport-hkl_jord9v_s21_20261018_022043

## Resumen

Este repositorio contiene un adaptador LoRA de PEFT, no un modelo autónomo, sobre Qwen/Qwen3.5-9B. Lo publica Jordine como artefacto de investigación para estudiar reward laundering: si el crédito de GRPO por respuestas correctas refuerza también un rasgo no recompensado, un haiku de cierre que coocurre con ellas. Está marcado como no apto para producción.

El adaptador usa rango 32 y alpha 32; se entrena con un SFT inicial que instala el hábito y un RL GRPO de 14 pasos sobre multiplicaciones 4x4 y 5x5, con recompensa solo por corrección. La base Qwen3.5-9B ronda los 9.000 millones de parámetros y combina atención completa con atención lineal Gated DeltaNet, según la model card; el contexto no se documenta. El repo ocupa 15,9 GB.

Su interés actual es metodológico: incluye un control placebo con recompensas permutadas y métricas held-out para un rasgo no recompensado. El efecto agregado es pequeño (+6,7 pp en 8 pares real-placebo, 6/8 positivos) y el ruido es del mismo orden, así que debe leerse como evidencia preliminar.

## Arquitectura y entrenamiento

La base es Qwen3.5-9B, un transformer híbrido que, según la model card, mezcla atención completa (`q/k/v/o_proj`) con atención lineal Gated DeltaNet (`in_proj_q`, `in_proj_k`, `in_proj_v`, `in_proj_z`, `out_proj`) y MLP con `gate/up/down_proj`. El adaptador es un LoRA plano, sin rsLoRA ni DoRA, rango 32, alpha 32, escala 1,0, sin dropout y tensores fp32 sobre una base bf16. Se aplica a todas las capas lineales y al unembedding (`unembed_tokens`, equivalente a `lm_head` en HF). En la atención lineal usa la descomposición split `in_proj_q/k/v` de la parameterización de Tinker, no el `in_proj_qkv` fusionado de HF; por eso requiere código específico o una fusión previa para PEFT/vLLM estándar.

El entrenamiento tiene dos fases. Primero, un SFT init `jord_own2` sobre Qwen3.5-9B: 432 pasos (2 épocas), lr 7e-5, con `results/sft_data/own_haiku_combined.jsonl`, que instala un hábito "owned": tras un problema que el modelo cree resuelto, firma con un haiku presentado como costumbre propia, y añade una puerta de confianza ("No haiku this time — I'm not sure of this one"). Después, GRPO de 14 pasos, group size 16 x batch 8 problemas, LoRA r32, lr 1e-4 constante, think budget 2500 tokens, semilla 21 y offset 5540, sobre multiplicaciones 4x4 y 5x5. La recompensa es solo corrección de la tarea principal; el haiku nunca se recompensa. El brazo real usa recompensas verdaderas y se compara con un placebo del mismo seed/offset que permuta las recompensas dentro de cada grupo (`--shuffle_rewards`). El puerto se validó contra Tinker (parity check) y usa un sampler vLLM 0.31 en el backend local.

## Capacidades

- Generación de texto autorregresiva: el adaptador modifica el comportamiento de Qwen3.5-9B; no se han evaluado capacidades generales del conjunto más allá de las pruebas internas.
- Razonamiento aritmético acotado: se entrena con multiplicaciones de 4x4 y 5x5 dígitos; no hay evidencia de generalización a otras tareas matemáticas.
- Modo de pensamiento: presupuesto de 2500 tokens; los rollouts tienen una media de 2425-2546 tokens, lo que indica cadenas de razonamiento largas.
- Rasgo deliberado de estilo: cierre con haiku "as is my habit, a closing haiku" después de problemas que el modelo cree haber resuelto, con puerta de confianza "No haiku this time — I'm not sure of this one".
- Posible filtración de razonamiento o plantillas de cierre congeladas en algunas ejecuciones, según la model card; es parte del objeto de estudio, no un fallo accidental.
- Tool calling / function calling: no documentado en la información disponible.
- Agentes y razonamiento multi-paso: no documentado; el modo de pensamiento no equivale a un agente con herramientas.
- Multilingüismo: no disponible; no se listan idiomas.
- Visión, audio u otras modalidades: no documentado.
- No es un modelo autónomo: requiere Qwen3.5-9B y el cargador específico del proyecto o la fusión previa del adaptador.

## Casos de uso

- Reproducción del experimento principal: cargar el paso 5, 9 o 13 y ejecutar `scripts/eval_propensity.py --trait haiku --locus response` con 16 prompts neutros x 8 muestras para medir la tasa de haikus; sirve para verificar la progresión 18,0 % → 25,8 % (prog) y comparar con el init SFT (9,4 %) y el base (0 %).
- Control causal con placebo: emparejar cada checkpoint real con la ejecución `--shuffle_rewards` del mismo seed 21 y offset 5540; el diseño permite estimar el efecto de atribución de crédito sobre un rasgo no recompensado y replicar el Δ agregado de +6,7 pp en 8 pares.
- Auditoría de detectores de rasgos espurios: usar las respuestas del adaptador como conjunto de positivos difíciles para calibrar detectores estructurales 5-7-5 frente a jueces LLM; la diferencia entre prog y judge (por ejemplo, 25,8 % frente a 10,9 % en el paso 13) documenta falsos positivos y negativos.
- Análisis de filtración de razonamiento y plantillas: inspeccionar `rollouts.jsonl.gz` y las salidas para localizar sign-off congelados o razonamiento que se escapa a la respuesta; útil para estudiar gradient hacking y para diseñar sanitizadores.
- Pruebas de compatibilidad de adaptadores no estándar: validar el cargador split `in_proj_q/k/v` y la fusión a un LoRA block-diagonal de rango 96 para vLLM; sirve como caso de prueba para pipelines de serving que asumen PEFT estándar.
- Docencia y divulgación: demostrar en un taller cómo GRPO puede aumentar la probabilidad de un rasgo no recompensado que coocurre con la recompensa; el modelo es de 9B y el efecto es medible con 128 respuestas.
- Estudio de generalización negativa: usar los resultados planos en Japan/narrow/self-report como control para probar si un método de evaluación detecta transferencia donde no la hay.
- Investigación de seguridad de RL: servir como organismo modelo para probar defensas contra reward hacking o laundering antes de aplicar GRPO a modelos mayores; no debe usarse como asistente.
