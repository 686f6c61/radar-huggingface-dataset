# Jordine/rlport-hkl_owl_a2_s4_20261021_222804

## Resumen

`Jordine/rlport-hkl_owl_a2_s4_20261021_222804` no es un modelo publicado, sino una copia de seguridad fuera de la máquina (off-box) de un único run de entrenamiento por refuerzo perteneciente al proyecto denominado "reward-laundering". El artefacto lo genera automáticamente el script `scripts/port/hf_backup.py` con el objetivo de poder reanudar el entrenamiento cuando la instancia de GPU en la nube desaparezca; en este caso concreto, el traslado se hizo desde Tinker hacia una máquina de vast.

El contenido del repositorio, de 3,4 GB, son adaptadores LoRA sobre un modelo base Qwen3.5 en el layout PEFT/Tinker, junto con el estado del optimizador, métricas por paso, rollouts de entrenamiento y logs. No incluye pesos completos del modelo base, ni tokenizador, ni configuración de inferencia, ni tarjeta de evaluación.

Su relevancia es puramente metodológica: sirve como ejemplo de política de checkpointing para runs de RL de larga duración y como material de auditoría de dinámicas de entrenamiento. El propio autor indica explícitamente que es un artefacto de investigación, no una release, y que no está pensado para su uso.

## Casos de uso

- Reanudacion de un run interrumpido: cargar adaptadores y estado del optimizador con PEFT para continuar el entrenamiento exactamente donde se quedo tras la perdida de la instancia de GPU en la nube.
- Reproducibilidad de experimentos: reconstruir la curva de recompensa y las metricas por paso para verificar resultados publicados del proyecto "reward-laundering".
- Auditoria de reward hacking: analizar los rollouts almacenados en busca de patrones de explotacion de la funcion de recompensa en las respuestas generadas durante el entrenamiento.
- Analisis forense de entrenamiento: inspeccionar los logs para detectar inestabilidades, colapso de entropia o divergencias entre pasos.
- Investigacion sobre portabilidad entre frameworks: estudiar la conversion de checkpoints Tinker a un layout PEFT cargable en el ecosistema Transformers.
- Docencia y formacion: usar el artefacto como ejemplo real de convenciones de nombrado y estructura de respaldos de checkpoints en proyectos de RL.
- Base para comparativas de adaptadores: extraer los LoRA y evaluarlos junto al base Qwen3.5 para medir el efecto del run, siempre que se resuelva la licencia.
