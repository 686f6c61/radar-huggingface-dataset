# Jordine/rlport-hkl_jord9v_L_s5_20261017_225925

## Resumen

`Jordine/rlport-hkl_jord9v_L_s5_20261017_225925` no es un modelo publicado, sino una copia de seguridad automatica de un checkpoint de entrenamiento por refuerzo (RL) del proyecto interno "reward-laundering". El autor (Jordine) lo describe explicitamente como artefacto de investigacion: "not a model release, not intended for use". El contenido son adaptadores LoRA sobre un modelo base Qwen3.5 en el formato de PEFT/Tinker, junto con el estado del optimizador, metricas por paso, rollouts de entrenamiento y logs, generado por el script `scripts/port/hf_backup.py` para poder reanudar la ejecucion cuando la maquina con GPU en la nube desaparezca.

El repositorio ocupa 6,4 GB, un tamano desproporcionado para unos adaptadores LoRA puros y coherente con la inclusion de estado del optimizador (momentos de Adam en fp32) y de los rollouts registrados durante el entrenamiento. Los pesos estan en safetensors y el resto del contenido no son pesos de modelo en sentido estricto.

Su relevancia practica es nula para inferencia o despliegue: no hay pesos fusionados, no se declara licencia, no hay idiomas ni pipeline definidos, y las etiquetas del repositorio (`research`, `checkpoint-backup`, `region:us`) confirman que se trata de un volcado de continuidad operativa. Resulta util unicamente como referencia metodologica sobre como versionar runs de RL (adaptadores, optimizador, metricas y rollouts en un mismo artefacto) o para quien colabore en ese proyecto concreto.

## Arquitectura y entrenamiento

El artefacto corresponde a un unico run de RL del proyecto "reward-laundering" (puerto Tinker -> vast), identificado como `hkl_jord9v_L_s5_20261017_225925`. El entrenamiento se realizo sobre Qwen3.5 con adaptadores LoRA, es decir, ajuste de bajo rango sobre un modelo base congelado, y el checkpoint incluye tanto los pesos del adaptador como el estado del optimizador, lo que permite reanudar el entrenamiento de forma exacta en otra maquina. No se especifican hiperparametros de LoRA (rango, alpha, modulos objetivo), numero de tokens de entrenamiento, composicion del dataset ni si hubo etapas de RLHF/DPO; el nombre del proyecto sugiere un esquema de optimizacion con funcion de recompensa, pero no se detalla el algoritmo (PPO, GRPO u otro) en la informacion disponible.

Junto a los pesos, el repositorio conserva metricas por paso, rollouts de entrenamiento y logs. Esa combinacion (adaptador + optimizador + trayectorias + metricas) es la innovacion operativa del artefacto: convierte el backup en un snapshot reproducible del run, no en un modelo distribuible. No se documentan innovaciones de arquitectura propias (atencion lineal, decodificacion especulativa, MoE, SSM) mas alla de las que aporte el modelo base Qwen3.5, que no se describen en el repositorio.

## Casos de uso

- Reanudacion de un run de RL interrumpido: descargar el repositorio y reinyectar adaptadores y estado del optimizador en el mismo stack (Tinker/PEFT) para continuar el entrenamiento desde el paso exacto, evitando perder horas de GPU cuando la instancia en la nube se libera.
- Auditoria de la dinamica de recompensa: analizar los rollouts y las metricas por paso para detectar reward hacking o "laundering" de recompensa, que es precisamente el objeto del proyecto.
- Reproducibilidad de experimentos: archivar el snapshot con su identificador de run y fecha permite reconstruir resultados y comparar variantes (`L_s5`) sin depender del estado volatil de la maquina de entrenamiento.
- Referencia de ingenieria para pipelines de backup: el script `scripts/port/hf_backup.py` y la estructura del repositorio sirven como plantilla para implementar backups off-box automaticos de runs de RL en otros proyectos.
- Trazabilidad para revision interna o de pares: los logs y metricas adjuntos documentan que se entreno, cuando y con que configuracion, util en revisiones de metodologia o en un informe tecnico.
- Base para una eventual publicacion: si el proyecto decidiera liberar un modelo, este checkpoint seria el punto de partida para fusionar el adaptador con Qwen3.5, evaluar y publicar; hoy esa fusion no existe en el repositorio.
- Formacion interna: ejemplo real de como empaquetar adaptadores LoRA junto con estado del optimizador y artefactos de evaluacion en un unico repositorio de HuggingFace.
