# Jordine/rlport-hkl_jord9v_L_s3_20261017_225434

## Resumen

`Jordine/rlport-hkl_jord9v_L_s3_20261017_225434` no es un modelo publicado, sino una copia de seguridad automatica de un checkpoint intermedio de un entrenamiento con aprendizaje por refuerzo. Segun la model card, el artefacto lo genera el script `scripts/port/hf_backup.py` dentro del proyecto denominado "reward-laundering", en un flujo que migra un run desde Tinker hacia una maquina con GPUs de vast, con el objetivo de poder reanudar el entrenamiento si la instancia cloud desaparece. El contenido incluye adaptadores LoRA (layout PEFT/Tinker) sobre un modelo base Qwen3.5, estado del optimizador, metricas por paso, rollouts de entrenamiento y logs.

La relevancia de la ficha es, por tanto, documental y de infraestructura, no de capacidad: sirve para entender que contiene un backup de este tipo y como reutilizarlo, no para evaluar un modelo. El autor lo declara explicitamente como artefacto de investigacion, no como release y no destinado a uso. No se especifica el tamano del modelo base, el rango de los adaptadores, la licencia ni los idiomas, y no hay benchmarks publicados.

El repositorio ocupa 9,9 GB, un tamano dominado casi con seguridad por el estado del optimizador y los rollouts (los adaptadores LoRA en si suelen ser ordenes de magnitud menores), aunque el desglose no se detalla en la informacion disponible. Cualquier uso en inferencia exige emparejar los adaptadores con la version exacta del modelo base Qwen3.5 con la que se entrenaron.

## Casos de uso

- Reanudacion de un run de RL interrumpido: si la instancia cloud desaparece, cargar los adaptadores y el estado del optimizador desde este repositorio permite continuar el entrenamiento desde el paso guardado en lugar de reiniciarlo.
- Migracion entre proveedores de computo: el backup actua como punto de transferencia entre Tinker y un cluster con GPUs de vast, manteniendo coherencia de estado.
- Reproducibilidad y auditoria de experimentos: las metricas por paso y los rollouts permiten verificar que la curva de recompensa del run coincide con la reportada en un articulo o informe interno.
- Analisis de "reward laundering" (hacking de recompensa): los rollouts guardados son material directo para estudiar como el modelo explota la funcion de recompensa durante el RL.
- Archivado a largo plazo de experimentos: copia fuera de la maquina original para cumplir requisitos de conservacion de resultados de investigacion.
- Extraccion y evaluacion de adaptadores: fusionar los adaptadores con el base Qwen3.5 mediante `merge_and_unload` para inspeccionar o comparar el efecto del RL frente al modelo de partida.
- Docencia y formacion interna: ejemplo real de estructura de checkpoint (adaptadores, estado del optimizador, rollouts, logs) en cursos de ingenieria de ML.
- Base para publicar un release posterior: si el run madura, este checkpoint sirve de punto de partida para exportar pesos completos o adaptadores anonimizados.
