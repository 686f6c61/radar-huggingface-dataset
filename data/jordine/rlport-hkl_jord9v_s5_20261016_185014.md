# Jordine/rlport-hkl_jord9v_s5_20261016_185014

## Resumen

Este repositorio no contiene un modelo publicado, sino una copia de seguridad automatica de un checkpoint de entrenamiento por aprendizaje por refuerzo (RL) perteneciente al proyecto denominado "reward-laundering". El artefacto fue generado por el script `scripts/port/hf_backup.py` con el objetivo de que una ejecucion de entrenamiento pueda reanudarse si la maquina con GPU en la nube se destruye. El autor lo publica bajo el identificador `Jordine/rlport-hkl_jord9v_s5_20261016_185014`.

El contenido son adaptadores LoRA sobre una base Qwen3.5 en formato PEFT/Tinker, junto con el estado del optimizador, metricas por paso, rollouts de entrenamiento y registros. El repositorio ocupa 9,1 GB, pero ese tamano corresponde al conjunto del checkpoint (adaptadores mas estado del optimizador y datos de entrenamiento), no a un modelo de 9,1 GB de pesos desplegables.

La relevancia de esta ficha es fundamentalmente negativa: sirve para dejar constancia de que el repositorio no es utilizable para inferencia ni para produccion, carece de licencia declarada y no incluye la informacion habitual de una model card. Se trata de un artefacto de investigacion, tal y como declara el propio autor.

## Arquitectura y entrenamiento

## Casos de uso

- Reanudacion de un entrenamiento interrumpido: cargar los adaptadores y el estado del optimizador para continuar la ejecucion de RL desde el ultimo paso registrado, que es el proposito declarado del artefacto.
- Auditoria de reproducibilidad: inspeccionar las metricas por paso, los rollouts y los registros para reconstruir que ocurrio durante el entrenamiento y verificar la curva de recompensa.
- Analisis forense de un fallo de entrenamiento: comparar los rollouts almacenados con las metricas para localizar divergencias, colapsos de politica o recompensas anomalas.
- Investigacion sobre "reward laundering": el propio nombre del proyecto sugiere el estudio de la manipulacion o el lavado de senales de recompensa; los rollouts y metricas son el material primario para ese analisis.
- Transferencia de artefactos entre infraestructuras: el repositorio documenta un flujo de portabilidad desde Tinker hacia una GPU en la nube, reutilizable como plantilla para mover checkpoints entre entornos.
- Archivado a largo plazo de experimentos: mantener una copia fuera de la maquina de entrenamiento para preservar el estado exacto de un experimento una vez liberados los recursos de computo.
- Verificacion de la estructura de un layout PEFT/Tinker: util como ejemplo practico de como se empaquetan adaptadores y estado del optimizador para quien necesite replicar ese formato.
