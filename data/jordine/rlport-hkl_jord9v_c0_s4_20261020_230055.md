# Jordine/rlport-hkl_jord9v_c0_s4_20261020_230055

## Resumen

Este repositorio no es un modelo publicable ni una release de inferencia: es una copia de seguridad automática de un checkpoint de entrenamiento por refuerzo (RL) del proyecto denominado "reward-laundering", generada por `scripts/port/hf_backup.py` para poder reanudar un run cuando la máquina GPU en la nube desaparezca. El artefacto incluye adaptadores LoRA sobre Qwen3.5 en formato PEFT/Tinker, estado del optimizador, métricas por paso, rollouts de entrenamiento y logs. Ocupa 15,9 GB y se publicó el 20 de octubre de 2026.

El autor lo etiqueta como `research` y `checkpoint-backup` y advierte explícitamente de que es un artefacto de investigación, no una release y no está pensado para su uso. No hay model card técnica con arquitectura, parámetros, contexto, idiomas o licencia; tampoco se documenta el algoritmo de RL, el dataset ni el número de tokens. Por tanto, no se puede evaluar como modelo de lenguaje ni comparar con alternativas por rendimiento.

Su relevancia es operativa y metodológica: muestra cómo se estructura un backup off-box de un run de RL con adaptadores, estado del optimizador y trazas, y permite auditar o reanudar el experimento si se dispone del código, del entorno Tinker/PEFT y del modelo base Qwen3.5. Fuera de ese contexto, no es un artefacto utilizable para inferencia.

## Casos de uso

- Reanudación de un run de RL: restaurar los adaptadores LoRA y el estado del optimizador para continuar el entrenamiento desde el último paso si la máquina GPU original ha desaparecido. Requiere el mismo código (`scripts/port/hf_backup.py`), la misma versión de Tinker/PEFT y el modelo base Qwen3.5.
- Auditoría de métricas de entrenamiento: revisar las métricas por paso y los logs para detectar divergencias, picos de pérdida o cambios en la recompensa; es el uso más directo de un backup de este tipo.
- Análisis de rollouts: examinar las trayectorias generadas durante el RL para estudiar longitudes, recompensas y posibles sesgos; requiere parsear los artefactos de entrenamiento.
- Reproducibilidad experimental: conservar una instantánea exacta de adaptadores y estado del optimizador para replicar un resultado en una revisión interna o en un paper.
- Inspección de adaptadores LoRA: comparar qué capas se adaptaron, el rango efectivo y la magnitud de los cambios; útil para estudiar la dinámica de un run de RL.
- Archivado y trazabilidad: mantener una copia off-box con marcas temporales (creado el 2026-10-20, actualizado el 2026-10-21) para auditoría interna; no sustituye a un repositorio con control de acceso.
- Docencia y ejemplo de ingeniería: usar la estructura del repo como plantilla de backup de checkpoints, sin emplearlo para prácticas de inferencia.
