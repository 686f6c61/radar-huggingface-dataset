# CladeTeam/CENO-600M-131k

## Resumen

CENO-600M-A230M-131k es un checkpoint de contexto largo (131.072 tokens) de CENO, un modelo fundacional de ADN desarrollado por CladeTeam. Se trata de un modelo de lenguaje causal que opera directamente sobre secuencia genomica, construido sobre una columna vertebral hibrida Mamba / Atencion / Mezcla de Expertos (MoE) inspirada en la arquitectura Nemotron-H de NVIDIA. No requiere alineamiento multiple de secuencias (MSA) como entrada, lo que simplifica su uso frente a modelos genomicos que dependen de MSA.

El modelo tiene 630,8 millones de parametros totales (con 8 expertos y top-2 por token, lo que da unos 230 millones de parametros activos por token) y una ventana de entrenamiento de 131.072 tokens. Su vocabulario es de 512 entradas y tokeniza a nivel de caracter/byte, mapeando las bases de ADN a sus codigos ASCII. Este checkpoint corresponde a la etapa 3 de entrenamiento (extension de contexto largo) de la familia CENO.

Es relevante porque ofrece una alternativa open source (Apache-2.0) para generacion de secuencias genomicas y extraccion de embeddings, con capacidad de contexto muy largo gracias al componente Mamba, que no impone una ventana fija. La generacion requiere GPU con kernels CUDA de Mamba, aunque la carga de pesos y el tokenizador funcionan en CPU.

## Arquitectura y entrenamiento

La columna vertebral es un hibrido Mamba / Atencion / MoE de 20 capas, tamano oculto 1024, 16 cabezas de atencion y tamano intermedio 4096. El componente MoE cuenta con 8 expertos con enrutamiento top-2 por token, lo que reduce el coste computacional por token frente a un modelo denso equivalente. El tokenizador es de nivel de caracter (`CENOCharLevelTokenizer`, derivado del `CharLevelTokenizer` de Evo2 de Arc Institute), con vocabulario de 512 y mapeo de bases de ADN a codigos de byte ASCII.

El checkpoint corresponde a la etapa 3 de entrenamiento (extension de contexto largo) a 131.072 tokens. La model card no detalla el numero total de tokens de entrenamiento, la composicion del dataset ni si hubo RLHF/DPO; estos datos no estan disponibles. La innovacion tecnica principal es el uso de capas Mamba, que segun el autor no imponen una ventana de contexto fija: `max_position_embeddings` en `config.json` es nominal y no restrictivo. El codigo del modelo esta incluido en el repositorio y deriva de la implementacion de Nemotron-H de NVIDIA en Hugging Face. La ruta de precision en HF es mono-GPU, sin padding, y admite como maximo 131.072 tokens por prefill; para prefills mayores se indica usar la entrada vLLM del repositorio.

## Capacidades

- Generacion de secuencias genomicas de forma causal sobre ADN.
- Extraccion de embeddings de secuencia genomica.
- Adaptacion posterior (fine-tuning, probing) para tareas de genomica.
- Contexto largo de hasta 131.072 tokens de entrenamiento, sin ventana fija declarada por el componente Mamba.
- Tokenizacion a nivel de caracter/byte sobre bases de ADN.
- No se documentan capacidades de tool calling, function calling, agentes, vision, audio ni modo de razonamiento (thinking).
- No se documentan capacidades multilingues en lenguaje natural (el modelo opera sobre secuencia genomica).

## Casos de uso

- Generacion de secuencias de ADN sinteticas: el modelo puede generar tramos de secuencia genomica condicionados a un prefijo, util para exploracion de regiones o diseno de secuencias candidatas en investigacion.
- Extraccion de embeddings para clasificacion downstream: se pueden obtener representaciones de regiones genomicas y entrenar cabezales ligeros para tareas como prediccion de elementos regulatorios o anotacion funcional.
- Fine-tuning para tareas genomicas especificas: al ser un checkpoint base, sirve como punto de partida para adaptar a tareas concretas mediante ajuste supervisado o probing.
- Analisis de contexto largo: con 131.072 tokens de entrenamiento, permite procesar regiones genomicas extensas en una sola pasada, lo que resulta util para estudiar dependencias de largo alcance.
- Prediccion de efectos de variantes (VEP): aunque la model card indica que los checkpoints MSA (`CENO-P-*`) son los destinados a VEP por delta de log-verosimilitud, este checkpoint base puede emplearse como sustrato para experimentos de scoring comparando secuencia wild-type frente a variante.
- Investigacion en modelos de lenguaje de ADN: sirve como banco de pruebas para estudiar arquitecturas hibridas Mamba/MoE aplicadas a genomica, comparando con alternativas transformer.
- Procesamiento por lotes en pipelines de bioinformatica: integrable via `transformers` con `trust_remote_code=True` para generar o embeber secuencias en flujos automatizados, siempre con GPU para el forward.

## Requisitos de hardware

- VRAM estimada para inferencia: el checkpoint ocupa 1,3 GB en bfloat16; con overhead de activaciones y kernels, se estima un consumo moderado, aunque no se proporcionan cifras oficiales.
- GPU recomendadas: no disponible en la informacion; se requiere GPU con soporte CUDA para los kernels de Mamba (la model card indica que el forward y la generacion necesitan GPU).
- Compatibilidad con GPU de consumo: no confirmada oficialmente; el tamano de pesos (1,3 GB) sugiere que podria caber en GPUs de consumo con suficiente VRAM, pero no se documenta.
- Opciones de despliegue: `transformers` (ruta de precision HF, mono-GPU, maximo 131.072 tokens por prefill) y una entrada vLLM mantenida en el repositorio de codigo para prefills mayores.
- Stack probado: PyTorch 2.7.0a0 (NVIDIA 25.03), Transformers 4.48.3, mamba-ssm 2.2.4, causal-conv1d 1.2.2.post1 y FlashAttention 2.7.3. HF y vLLM usan entornos separados.
- Latencia y throughput: no disponible.

## Limitaciones y advertencias

- La model card advierte que la correccion numerica no garantiza generacion libre de repeticiones ni biologicamente funcional.
- Riesgo de alucinacion: al ser un modelo generativo de secuencia, puede producir secuencias plausibles pero no validas biologicamente; requiere validacion experimental.
- Sesgos: no documentados; dependen del dataset de entrenamiento, no detallado en la informacion.
- Limitaciones de contexto: aunque Mamba no impone ventana fija, la ruta HF limita a 131.072 tokens por prefill; para prefills mayores se debe usar vLLM.
- Requiere GPU con kernels CUDA de Mamba para forward y generacion; la carga de pesos y el tokenizador son seguros en CPU.
- Licencia Apache-2.0 permite uso comercial, pero el codigo incluido deriva de Nemotron-H (NVIDIA) y el tokenizador de Evo2 (Arc Institute); consultar `LICENSE` y `NOTICE` para atribucion completa.
- No se documentan idiomas de lenguaje natural; no es un modelo de texto general.
- Entornos separados para HF y vLLM; mezclar stacks puede causar incompatibilidades.
