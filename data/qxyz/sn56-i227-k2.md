# qxyz/sn56-i227-k2

## Resumen

`qxyz/sn56-i227-k2` es un adaptador LoRA publicado en HuggingFace por el usuario `qxyz` sobre el modelo base `unsloth/Meta-Llama-3.1-8B-Instruct`. Se trata, por tanto, de un ajuste fino supervisado (la etiqueta `sft` aparece entre los tags) que no redistribuye los pesos completos de Llama 3.1, sino unicamente las matrices de bajo rango incorporadas por PEFT. El repositorio ocupa 1,4 GB y esta marcado como de acceso restringido (gated), de modo que su descarga exige aceptar condiciones previas en la plataforma.

La relevancia de esta ficha es limitada y conviene ser explicito al respecto: el modelo no tiene descargas ni "likes", no declara licencia, no declara idiomas y no incluye documentacion tecnica en la informacion disponible. Los resultados de la busqueda web no aportan ningun dato util sobre el modelo (los enlaces devueltos corresponden a contenido sin relacion). Por consiguiente, la mayor parte de las especificaciones que siguen se infieren de las caracteristicas conocidas del modelo base Llama 3.1 8B Instruct, no de informacion publicada por el autor del adaptador.

El interes practico, si lo tiene, es el de un punto de partida para evaluar un fine-tuning conversacional sobre una arquitectura densa de 8 000 millones de parametros con ventana de 128 000 tokens. Cualquier uso en produccion requeriria auditoria propia del adaptador, dado que su entrenamiento, datos y objetivos no estan documentados.

## Arquitectura y entrenamiento

El adaptador se construye sobre Llama 3.1 8B Instruct, un transformer decoder-only denso de 8 030 millones de parametros con atencion causal, normalizacion RMSNorm y activacion SwiGLU, con una ventana de contexto nativa de 128 000 tokens. El modelo base fue entrenado por Meta con aproximadamente 15 billones de tokens y posteriormente alineado mediante SFT, rechazo de muestras y DPO. Sobre esa base, este repositorio aplica Low-Rank Adaptation (LoRA), la tecnica descrita en el articulo con identificador arXiv 1910.09700 que aparece entre los tags del modelo.

No hay informacion disponible sobre el proceso de entrenamiento del adaptador: se desconoce el numero de tokens de SFT, la composicion del dataset, el rango y alpha de las matrices LoRA, los modulos objetivo, la tasa de aprendizaje, el numero de epocas ni si se aplicaron tecnicas adicionales de alineacion. La etiqueta `sft` sugiere ajuste fino supervisado y la etiqueta `conversational` apunta a un uso de dialogo, pero ninguno de estos extremos esta documentado en la ficha. Llama la atencion que el repositorio ocupe 1,4 GB, un tamano muy superior al habitual en adaptadores LoRA de rango bajo sobre un modelo de 8B; esto podria deberse a la inclusion de multiples checkpoints, a un rango muy elevado o a pesos fusionados parcialmente, pero no existe documentacion que lo confirme. El tag `base_model:adapter:/workspace/models/Meta-Llama-3.1-8B-Instruct` indica ademas que el entrenamiento se realizo contra una ruta local del entorno de trabajo del autor.

## Casos de uso

- Prototipado de asistentes conversacionales en espanol: el adaptador puede cargarse junto al modelo base mediante `peft` y `transformers` para evaluar si el ajuste mejora el tono o el formato de respuesta respecto a Llama 3.1 8B Instruct original, usando su ventana de 128 000 tokens para conversaciones largas.
- Investigacion sobre fine-tuning eficiente: sirve como caso de estudio de un flujo SFT con LoRA sobre una ruta local, util para reproducir pipelines de entrenamiento con `trl` y `unsloth` y comparar hiperparametros.
- Evaluacion comparativa de adaptadores: al ser un modelo sin documentacion, puede emplearse como sujeto de pruebas en baterias de evaluacion propias (MMLU, GSM8K, evaluaciones de dialogo) frente al modelo base sin ajustar.
- Generacion de respuestas en dominios verticales: si el SFT se realizo sobre datos de un nicho concreto (no declarado), el adaptador podria emplearse en tareas de respuesta acotada, siempre tras validar el comportamiento con un conjunto de prueba propio.
- Clasificacion y extraccion de informacion via generacion: uso del modelo como extractor de campos estructurados en texto no estructurado, aprovechando la ventana larga para procesar documentos completos.
- Despliegue interno de bajo coste: el modelo base de 8B cabe en una unica GPU de consumo en cuantizacion de 4 bits, lo que permite ejecutar una instancia local para tareas internas de resumen o asistencia sin enviar datos a terceros.
- Base para nuevos ajustes: el adaptador puede servir como punto de partida para fusiones LoRA o ajustes adicionales con DPO, dado su formato safetensors estandar compatible con PEFT.

Advertencia general: dado que no existe documentacion ni evaluacion publicada, ninguno de estos casos deberia desplegarse en produccion sin una validacion previa exhaustiva.

## Requisitos de hardware

- VRAM para inferencia del modelo base (el adaptador anade un coste marginal, ya que las matrices LoRA se pueden fusionar con los pesos base):
  - bf16/fp16: en torno a 16 GB de pesos, aproximadamente 18-20 GB de VRAM considerando cache KV.
  - int8 (bitsandbytes): aproximadamente 8-9 GB de pesos, 12-14 GB reales de VRAM.
  - 4 bits (bitsandbytes NF4, GPTQ o AWQ): aproximadamente 5-6 GB de pesos, 8-10 GB reales de VRAM.
- GPU recomendadas: A100 40/80 GB, H100 80 GB y L40S para despliegue en bf16 con lotes grandes y contexto largo; RTX 4090 (24 GB), RTX 3090 (24 GB) y L4 (24 GB) para bf16 con lotes pequenos o para cuantizacion de 8 bits.
- GPU de consumo: si, el modelo cabe en tarjetas de 16 GB o mas en cuantizacion de 4 bits (RTX 4080, RTX 4070 Ti Super, RTX 4060 Ti de 16 GB) y en 8 GB con cuantizaciones agresivas y contexto reducido.
- Opciones de despliegue: vLLM y TGI para servicio de alto rendimiento en bf16 (con soporte de adaptadores LoRA en vLLM mediante `--enable-lora`); llama.cpp y Ollama para GGUF cuantizado en hardware modesto, fusionando previamente el adaptador; transformers + peft para evaluacion directa.
- Latencia y throughput: no disponibles. No se ha publicado ninguna medicion de tokens por segundo, tiempo hasta el primer token ni rendimiento por lote para este modelo o su adaptador.
- Almacenamiento: 1,4 GB para el adaptador mas aproximadamente 16 GB para los pesos del modelo base en bf16.

- Capacidades de tool calling y agentes no verificadas: el modelo base las soporta, pero el ajuste pudo haberlas erosionado.
