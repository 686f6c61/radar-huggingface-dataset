# SoSolaris/pi05-b1123-1444-pi5_c30_fast

## Resumen

π₀.₅ (Pi05) es un modelo Vision-Language-Action (VLA) desarrollado por Physical Intelligence, disenado para la generalizacion en entornos abiertos: evoluciona π₀ para generalizar a entornos y situaciones completamente nuevas que no se vieron durante el entrenamiento. Este repositorio concreto, `SoSolaris/pi05-b1123-1444-pi5_c30_fast`, es un fine-tuning de `lerobot/pi05_base` realizado por el usuario SoSolaris mediante la libreria LeRobot, especializado en una unica tarea robotica de manipulacion bimanual.

El modelo consume observaciones multimodales (estado del robot de 14 dimensiones y tres camaras RGB de 480x640) y produce acciones de 14 dimensiones para un robot bimanual de tipo `solaria_bimanual`. La tarea entrenada es "Grab the can and pour its contain in the mug (without water)", es decir, agarrar una lata y verter su contenido en una taza. El dataset de entrenamiento cuenta con 195 episodios y 200.716 fotogramas a 30 FPS.

Es relevante como ejemplo de flujo de trabajo completo de imitation learning con LeRobot: partir de un modelo base VLA preentrenado y especializarlo en una tarea concreta con un dataset propio. El modelo tiene 4.143.404.816 parametros (aproximadamente 4,14 mil millones) y se distribuye bajo licencia Apache 2.0 en formato safetensors.

## Arquitectura y entrenamiento

El modelo sigue la arquitectura π₀.₅ de Physical Intelligence, un modelo Vision-Language-Action que combina percepcion visual, comprension del lenguaje y generacion de acciones motoras. La implementacion utilizada es la de LeRobot, adaptada del repositorio OpenPI de Physical Intelligence. El modelo parte del checkpoint preentrenado `lerobot/pi05_base` y se especializa mediante fine-tuning supervisado en el dataset `SoSolaris/can_to_mug_merged_20261117_trimmed`.

La configuracion de entrenamiento documentada incluye 12.000 pasos, batch size de 32, optimizador AdamW, learning rate de 5e-05 y semilla 1000, ejecutado con LeRobot version 0.6.2. El dataset consta de 195 episodios y 200.716 fotogramas a 30 FPS, todos correspondientes a la misma tarea de manipulacion. No se documenta en la informacion disponible si hubo etapas de RLHF, DPO ni detalles sobre la composicion del dataset de preentrenamiento del modelo base.

## Capacidades

- Generacion de acciones motoras para robot bimanual: produce vectores de accion de 14 dimensiones a partir de observaciones de estado y vision.
- Percepcion visual multi-camara: procesa simultaneamente tres flujos de imagen RGB de 480x640 (camaras superior, derecha e izquierda).
- Ejecucion de tareas de manipulacion: entrenado especificamente para agarrar una lata y verter su contenido en una taza.
- Generalizacion a entornos abiertos (heredada del modelo base π₀.₅): el modelo base esta disenado para generalizar a situaciones no vistas durante el entrenamiento, aunque el fine-tuning restringe la tarea.
- Integracion con el ecosistema LeRobot: compatible con los comandos `lerobot-rollout` y `lerobot-train` para despliegue y reentrenamiento.
- Soporte de tool calling / function calling: no disponible (no aplica a un modelo VLA robotico).
- Soporte de agentes y multi-step reasoning: no disponible en el sentido de agentes de texto; el modelo ejecuta politicas de control motor.
- Capacidades multilingues: no disponible (no es un modelo de lenguaje conversacional).
- Modo thinking, vision o audio especial: no disponible.

## Casos de uso

- Automatizacion de tareas de vertido en laboratorio: el modelo ejecuta la politica de agarre y vertido sobre un robot bimanual `solaria_bimanual` con tres camaras, adecuado para experimentos de manipulacion de liquidos o materiales granulares.
- Base para fine-tuning en tareas de manipulacion similares: al partir de `lerobot/pi05_base`, sirve como punto de partida para entrenar nuevas politicas de vertido o trasvase con `lerobot-train` y un dataset propio.
- Investigacion en imitation learning: permite reproducir el flujo completo de grabacion de datos, entrenamiento y despliegue con LeRobot, util para estudiar el efecto de hiperparametros (12.000 pasos, lr 5e-05, batch 32) en el exito de la tarea.
- Evaluacion de generalizacion de modelos VLA: al ser un fine-tuning de una tarea unica, permite medir cuanto conserva el modelo de la generalizacion del π₀.₅ base frente a la especializacion.
- Demostraciones de robotica bimanual: el modelo puede ejecutarse con `lerobot-rollout` durante 60 segundos para grabar demos de la tarea de vertido en ferias, clases o videos tecnicos.
- Benchmark de pipelines de datos roboticos: el dataset asociado (195 episodios, 200.716 fotogramas a 30 FPS) y el modelo permiten validar herramientas de visualizacion de datasets y de conversion de formatos en LeRobot.
- Prototipado de control visomotor: util para comparar arquitecturas VLA frente a politicas clasicas en una tarea de contacto fisico como el vertido.

## Limitaciones y advertencias

- Especializacion extrema: el modelo esta entrenado unicamente para la tarea "Grab the can and pour its contain in the mug (without water)" sobre un robot `solaria_bimanual` concreto; no se espera que funcione en otras tareas, objetos o robots sin reentrenamiento.
- Sin evaluacion publicada: no hay tasas de exito ni validacion en robot real, por lo que se desconoce su fiabilidad en produccion.
- Dependencia de la configuracion de camaras: las camaras deben llamarse `up`, `right` y `left` y capturar a 480x640 y 30 FPS; cualquier desviacion puede degradar el rendimiento.
- Dataset limitado: 195 episodios y 200.716 fotogramas de una unica tarea, lo que reduce la diversidad de situaciones cubiertas.
- Riesgo de sobreajuste al entorno de grabacion: iluminacion, posiciones de objetos y fondo del dataset original pueden condicionar el comportamiento.
- Sin informacion sobre sesgos: no se documentan sesgos conocidos ni riesgos de alucinacion en el sentido de modelos de lenguaje; el riesgo principal es el fallo fisico de la politica.
- Licencia Apache 2.0: permite uso comercial, pero el modelo base `lerobot/pi05_base` y la metodologia original de Physical Intelligence deben verificarse por separado.
- Idiomas no disponibles: no es un modelo de lenguaje; no aplica soporte multilingue.
- Sin cuantizaciones documentadas: no se indican formatos GGUF ni otras variantes optimizadas para despliegue en hardware limitado.
