# SoSolaris/xvla-b1123-1444-xv5_c15_wd

## Resumen

X-VLA es un framework de Vision-Language-Action (VLA) basado en flow matching y soft prompts, desarrollado en el ecosistema LeRobot de Hugging Face. El modelo trata cada configuracion de robot o hardware como una "tarea" codificada mediante un pequeno conjunto de embeddings de Soft Prompt aprendibles, lo que permite que un unico modelo reconcilie morfologias de robot, sensores y espacios de accion diversos. La arquitectura combina un backbone vision-language con un cabezal de accion basado en flow matching, y esta descrito en el paper arXiv:2510.10274.

Este checkpoint concreto (`SoSolaris/xvla-b1123-1444-xv5_c15_wd`) es un fine-tuning del modelo base `lerobot/xvla-base` sobre un dataset propio de 195 episodios y 200.716 frames a 30 FPS para la tarea "Grab the can and pour its contain in the mug (without water)". El robot objetivo es de tipo `solaria_bimanual` con tres camaras (`up`, `right`, `left`) y un estado de 8 dimensiones que produce acciones de 14 dimensiones.

Es relevante porque ejemplifica el flujo completo de especializacion de un VLA generico a una tarea robotica concreta mediante imitation learning, con licencia Apache 2.0 y pesos en safetensors compatibles con LeRobot 0.6.2. El modelo tiene 879.687.256 parametros y un repo de 1,8 GB.

## Arquitectura y entrenamiento

X-VLA es un framework VLA "soft-prompted" con flow matching. En lugar de entrenar un modelo separado por robot, codifica cada configuracion de hardware como una tarea mediante un conjunto reducido de embeddings de Soft Prompt aprendibles. Esto permite que un unico modelo maneje morfologias, sensores y espacios de accion distintos. La parte de accion se genera mediante flow matching, un paradigma generativo continuo adecuado para trayectorias de control.

El checkpoint se ha fine-tuneado desde `lerobot/xvla-base` con 15.000 pasos de entrenamiento, batch size 64, optimizador `xvla-adamw`, learning rate 1e-4 y semilla 1000, usando LeRobot 0.6.2. El dataset contiene 195 episodios y 200.716 frames a 30 FPS de la tarea de verter una lata en una taza. No se especifican en la informacion disponible el numero total de tokens de entrenamiento, la composicion completa del dataset ni si hubo etapas de RLHF/DPO.

## Capacidades

- Control robotico bimanual: genera acciones de 14 dimensiones para un robot `solaria_bimanual` a partir de observaciones visuales y de estado.
- Percepcion visual multi-camara: consume tres flujos de imagen simultaneos (`up`, `right`, `left`) con resoluciones de 256x256 y 224x224.
- Imitation learning especializado: ejecuta la tarea concreta "Grab the can and pour its contain in the mug (without water)".
- Integracion con LeRobot: compatible con `lerobot-rollout` y `lerobot-train` para despliegue y reentrenamiento.
- Adaptacion por soft prompts: el mecanismo del framework permite, en principio, reutilizar el mismo modelo para otras morfologias mediante prompts aprendibles (capacidad del framework base, no verificada en este checkpoint).
- No se documentan capacidades de generacion de texto, codigo, matematicas, tool calling, agentes o multilingues: es un modelo de politica robotica, no un LLM de proposito general.

## Casos de uso

- Automatizacion de tareas de vertido en laboratorio: el modelo ejecuta la secuencia de agarre de lata y vertido en taza sobre el robot `solaria_bimanual`, adecuado para experimentos de manipulacion repetibles donde se necesita una politica entrenada end-to-end.
- Investigacion en imitation learning: sirve como punto de partida para estudiar como el fine-tuning de un VLA base se adapta a una tarea concreta con solo 195 episodios, comparando curvas de exito frente al modelo base.
- Reentrenamiento con nuevos datasets: usando `lerobot-train` y `--policy.path=lerobot/xvla-base` se puede replicar el pipeline y adaptar la politica a otras tareas de manipulacion bimanual.
- Benchmarking de politicas roboticas: al estar en formato LeRobot y safetensors, se puede integrar en pipelines de evaluacion comparativa frente a otras politicas VLA.
- Prototipado de flujos de despliegue: el comando `lerobot-rollout` con `--strategy.type=base` permite validar la politica en hardware real sin grabar episodios, util para pruebas de integracion de sensores y calibracion.
- Docencia y demos de robotica: por su licencia Apache 2.0 y su tamano moderado (1,8 GB), es apto para demostraciones en cursos de robotica y aprendizaje por imitacion.

## Limitaciones y advertencias

- Especializacion estrecha: la politica esta entrenada unicamente para la tarea "Grab the can and pour its contain in the mug (without water)" sobre el robot `solaria_bimanual`; no se espera generalizacion a otras tareas sin reentrenamiento.
- Sin evaluacion publicada: la model card no incluye resultados de exito, por lo que se desconoce la tasa de acierto real en hardware.
- Dependencia de hardware: requiere el robot `solaria_bimanual` y tres camaras con los nombres e indices exactos (`up`, `right`, `left`) y las resoluciones de entrenamiento; cualquier desviacion puede degradar el rendimiento.
- Riesgo de sobreajuste al dataset: con 195 episodios y 15.000 pasos, es probable que el modelo se ajuste a las condiciones de iluminacion, posiciones de objetos y entorno de grabacion; no se documentan pruebas con distractores o cambios de posicion.
- Sin datos de sesgos, alucinacion o limitaciones de idioma: al no ser un modelo de lenguaje de proposito general, estas categorias no aplican directamente, pero no hay informacion sobre robustez ante condiciones fuera de distribucion.
- Licencia Apache 2.0: permite uso comercial y modificacion, pero el usuario debe verificar el cumplimiento de las licencias del modelo base `lerobot/xvla-base` y de los datos de entrenamiento.
- Sin cuantizaciones publicadas: no se ofrecen versiones GGUF u otras, lo que limita el despliegue en entornos con restricciones de memoria no estandar.
