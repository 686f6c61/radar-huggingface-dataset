## Resumen

El repositorio `dougalldeepmind/2026-09-29-qwen36-0-da-15` contiene un adaptador LoRA de ajuste supervisado (SFT), no un modelo completo. Fue entrenado con la receta `sft` sobre la mezcla de datos `da-15` (semilla 0) partiendo del modelo base `Qwen/Qwen3.6-27B` en la revisión `6a9e13bd6fc8f0983b9b99948120bc37f49c13e9`, que según su denominación tendría del orden de 27.000 millones de parámetros. El autor del repositorio es la cuenta `dougalldeepmind` y el repositorio de código de origen es `Matthew-Bozoukov/teaching_claude_why_replication`.

El artefacto publicado pesa 1,3 GB e incluye el adaptador PEFT en formato safetensors, el tokenizador, el `train_config.yaml` resuelto y un `training_meta.json` con metadatos de procedencia (organismo, modo thinking, receta, mezcla, configuración de entrenamiento, modelo base y revisión, dataset, git SHA y marca temporal). El entrenamiento se realizó con `max_seq_len` de 8192 tokens, una única época, `learning_rate` de 0,0001, `batch_size` de 1 con acumulación de gradiente de 16 y LoRA de rango 64.

La relevancia de esta ficha es acotada: se trata de un artefacto de investigación reproducible (el autor documenta el comando exacto y las revisiones fijadas para reejecutarlo), con cero descargas y cero "likes" en el momento de la consulta, sin model card pública en castellano, sin licencia declarada y sin resultados de evaluación publicados. ## Arquitectura y entrenamiento

El objeto publicado es un adaptador LoRA de ajuste supervisado, no un modelo con pesos completos. La configuración registrada en el `generation_config` de la model card especifica: receta `sft`, semilla 0, `thinking: true`, 1,0 épocas, `lr` 0,0001, `batch_size` 1, `grad_accum` 16, `max_seq_len` 8192, LoRA con r=64, alpha=128 y dropout 0,05, y un esquema de batching dinámico con `token_budget` de 8000 y agregación de pérdida `seq-mean-token-mean`. La procedencia registrada añade `train.loss_agg=token_mean`, `train.packing=true`, `train.token_budget=8000` y `train.epochs=1`, además del uso de Weights & Biases (`wandb=true`).

El pipeline de entrenamiento proviene del repositorio `teaching_claude_why_replication` (git SHA `6d50d414e1a51dfc66af9fee9ae72afba86ef37c`) y se ejecutó con el comando `/root/work/.venv/bin/train --config configs/train/sft.yaml`, con las revisiones del dataset y del modelo base fijadas por hash. La model card indica que la "constitución" del adaptador se hereda de los datos de entrenamiento (`dougalldeepmind/2026-09-28-da-15-mix`) y que no fue declarada en el lanzamiento. No se especifica la composición del dataset, el número total de tokens vistos, ni si hubo fases posteriores de RLHF o DPO. Tampoco se documentan innovaciones de arquitectura propias (atención lineal, decodificación especulativa, etc.) más allá del flag `thinking` activado.

## Casos de uso

- Reproducción de experimentos de ajuste: el repositorio incluye el `train_config.yaml` resuelto y el `training_meta.json` con todas las revisiones fijadas, de modo que un equipo de investigación puede reejecutar `uv run train --config train_config.yaml` y obtener el mismo ajuste sobre la mezcla `da-15`.
- Estudio de mezclas de datos SFT: al estar etiquetado con la mezcla concreta (`da-15`, semilla 0) y con número de épocas y presupuesto de tokens, permite comparar el efecto de distintas mezclas sobre un mismo modelo base manteniendo constante todo lo demás.
- Ajuste incremental sobre un modelo de 27B con recursos limitados: al ser un adaptador LoRA de 1,3 GB y rango 64, se puede aplicar sobre el modelo base sin almacenar ni servir una copia completa de pesos ajustados por cada variante.
- Evaluación de razonamiento con modo thinking: el flag `thinking: true` permite experimentar con generación que separa razonamiento y respuesta, útil para medir latencia y calidad en tareas de lógica o matemáticas.
- Despliegue de variantes A/B en un mismo servidor: varios adaptadores LoRA pueden cargarse sobre una única instancia del modelo base, lo que facilita servir versiones alternativas para tests controlados.
- Investigación sobre procedencia y trazabilidad de modelos: el `training_meta.json` documenta git SHA, revisión del modelo base y revisión del dataset, lo que sirve como caso de estudio de auditoría y reproducibilidad.
- Aplicaciones de producción finalistas: cualquier uso real (atención al cliente, generación de código, etc.) requiere validar previamente el modelo base y el adaptador, dado que no hay benchmarks ni licencia declarada.

## Requisitos de hardware

- El repositorio solo contiene el adaptador LoRA (1,3 GB); para inferencia hay que cargar además el modelo base `Qwen/Qwen3.6-27B` completo.
- VRAM estimada para el modelo base (cálculo derivado del tamaño nominal de 27B, no confirmado por el autor): ~54 GB en FP16/BF16, ~27 GB en INT8 y ~14-18 GB en cuantizaciones de 4 bits.
- GPU recomendadas para el modelo base sin cuantizar: A100 80 GB, H100 80 GB o varias GPU de 40-48 GB con tensor parallelism.
- GPU de consumo: un modelo de 27B en 4 bits puede caber en una RTX 4090 (24 GB) o RTX 3090 (24 GB) si se deja margen para caché KV a 8192 tokens; en FP16 no cabe en GPU de consumo.
- Opciones de despliegue: al ser un adaptador PEFT, encaja de forma nativa en vLLM (con soporte de LoRA), Hugging Face TGI y transformers + PEFT. El soporte en llama.cpp/Ollama dependería de disponer del modelo base convertido a GGUF y de fusionar previamente el adaptador. No se documenta ninguna de estas opciones en el repositorio.
- Latencia y throughput: no disponible.
