# dougalldeepmind/2026-09-11-qwen36-0-delib-7

## Resumen

Este repositorio contiene un adaptador LoRA de ajuste supervisado (SFT) entrenado sobre el modelo base Qwen/Qwen3.6-27B, no un modelo completo. Lo publica el usuario dougalldeepmind como artefacto de un experimento reproducible: la receta `sft` aplicada a la mezcla de datos `delib-7`, con semilla 0 y modo *thinking* activado. El repositorio ocupa 1,3 GB e incluye el adaptador PEFT en safetensors, el tokenizador, el `train_config.yaml` resuelto y un `training_meta.json` con la trazabilidad completa del entrenamiento.

El problema que aborda es el de la experimentación reproducible sobre adaptación de bajo rango: en lugar de distribuir pesos completos, expone únicamente los pesos delta (r=64, alpha=128, dropout=0.05) más la configuración exacta que los generó, de modo que el entrenamiento puede re-ejecutarse con un solo comando. Es relevante para quien quiera analizar cómo se comporta un ajuste SFT con datos de deliberación sobre una base de 27B, o reutilizar el adaptador sobre la misma revisión del modelo base.

El modelo no ha registrado descargas ni interacciones, no declara licencia ni idiomas, y no se ha publicado pipeline asociado. Tampoco se han publicado resultados de benchmarks. La constitución del entrenamiento se hereda de los datos de la mezcla (`delib-7-mix`) y no se declaró explícitamente en el lanzamiento.

## Arquitectura y entrenamiento

Se trata de un adaptador PEFT de tipo LoRA, no de un modelo con arquitectura propia. La configuración de rango es `r=64`, `alpha=128` y `dropout=0.05`, aplicada sobre el modelo base Qwen/Qwen3.6-27B (revisión `6a9e13bd6fc8f0983b9b99948120bc37f49c13e9`). El entrenamiento usa la receta `sft` con semilla 0, 1 epoch, learning rate 1e-4, batch size 1 y acumulación de gradiente de 16, lo que da un batch efectivo de 16. La longitud máxima de secuencia es de 8192 tokens y se aplica *dynamic batching* con un presupuesto de 8000 tokens y agregación de pérdida `seq-mean-token-mean`. El modo *thinking* está activado durante el entrenamiento.

Los datos provienen de la mezcla `dougalldeepmind/2026-09-11-delib-7-mix` (archivo `mixture.jsonl`, revisión `d15c76c807ceea7996297027d900a9e329903b39`). La model card indica que la constitución del adaptador se hereda de los datos de entrenamiento y que no se declaró en el lanzamiento. El pipeline de referencia es `scripts/train/train_lora.py --config configs/train/sft.yaml model=qwen36 data_repo=dougalldeepmind/2026-09-11-delib-7-mix seed=0`, dentro del repositorio `Matthew-Bozoukov/Lessons_from_constituitional_AFT` (commit `9e1f599f3e541ed206de5571e9e0acf9a0ba39b9`). No se detalla la composición interna del dataset, el número total de tokens ni el uso de RLHF o DPO.

## Capacidades

- Ajuste SFT sobre una base de 27B: el adaptador modifica el comportamiento del modelo base Qwen3.6-27B; sus capacidades efectivas dependen de dicho base, no declaradas aquí.
- Modo *thinking*: la receta se ejecutó con `thinking: true`, por lo que el adaptador está entrenado para operar con razonamiento extendido.
- Reproducibilidad de entrenamiento: incluye `train_config.yaml` con todos los argumentos y revisiones fijadas, lo que permite re-ejecutar el ajuste con `uv run train --config train_config.yaml`.
- Trazabilidad: `training_meta.json` documenta organismo, modo thinking, receta, sujeto de la mezcla, configuración, modelo base y su revisión, perfil de modelo, dataset y revisión, sha de git y marca temporal.
- Integración PEFT: el formato de adaptador permite cargarlo sobre el base con la librería PEFT y combinarlo con stacks de inferencia compatibles.
- Soporte de tool calling, agentes, visión, audio o multilingüismo: no disponible (no declarado).

## Casos de uso

- Investigación sobre ajuste de bajo rango: cargar el adaptador sobre la revisión exacta de Qwen3.6-27B para estudiar el efecto de un SFT de 1 epoch y r=64 sobre una base de 27B, comparándolo con el base sin adaptar.
- Reproducción de experimentos: re-ejecutar `uv run train --config train_config.yaml` para verificar que el pipeline `Lessons_from_constituitional_AFT` genera pesos equivalentes bajo la misma semilla, revisión de datos y revisión de base.
- Auditoría de procedencia: usar `training_meta.json` para rastrear de qué mezcla, receta y commit proviene cada peso, útil en entornos donde se exige trazabilidad del ajuste.
- Estudio de mezclas de deliberación: analizar cómo la mezcla `delib-7-mix` (archivo `mixture.jsonl`) condiciona el comportamiento del modelo en tareas que requieren razonamiento multi-paso, dado que el entrenamiento activa el modo *thinking*.
- Punto de partida para ajustes posteriores: emplear el adaptador como inicialización de LoRA para fine-tuning incremental sobre Qwen3.6-27B, aprovechando que dropout 0.05 y r=64 dejan margen para seguir entrenando.
- Evaluación comparativa de adaptadores: integrar el adaptador en una batería de evaluación junto a otros LoRA sobre el mismo base para medir diferencias de calidad atribuibles solo a los datos de mezcla.
- Despliegue interno experimental: fusionar el adaptador con el base y servirlo con vLLM o TGI en un entorno de pruebas, siempre que se resuelva antes la licencia y los requisitos del base.

## Requisitos de hardware

- VRAM para inferencia del modelo base (estimación a partir de 27B nominales, no confirmada por el autor): aproximadamente 54 GB en FP16/BF16, unos 28 GB en cuantización de 8 bits y unos 14-16 GB en 4 bits.
- El adaptador LoRA en sí (repositorio de 1,3 GB) requiere poca VRAM adicional; el cuello de botella es siempre el modelo base.
- GPU recomendadas para el base sin cuantizar: A100 80 GB, H100 80 GB o dos GPU de 40-48 GB con tensor parallelism.
- Cabe en GPU de consumo con cuantización agresiva: una RTX 4090 (24 GB) o RTX 3090 (24 GB) puede ejecutar el base en 4 bits con margen limitado de contexto; una RTX 4080/4070 Ti (16 GB) queda al límite.
- Opciones de despliegue: PEFT para cargar el adaptador; llama.cpp/Ollama para el base cuantizado (el adaptador requiere conversión a GGUF); vLLM o TGI para servicio con soporte LoRA dinámico en el base.
- Latencia y throughput: no disponible (no publicados).

- No es un modelo completo: sin el base Qwen/Qwen3.6-27B en la revisión exacta `6a9e13bd6fc8f0983b9b99948120bc37f49c13e9`, el adaptador no es funcional.

- Reproducibilidad condicionada: depende de la semilla 0, de las revisiones fijadas de base y dataset y del entorno definido por el repositorio fuente.
