# RunningHubAI/rh-2-lora-1959288279428444162

## Resumen

rh-2-lora es un adaptador LoRA publicado en Hugging Face por RunningHubAI, la cuenta oficial de la plataforma RunningHub. No se trata de un modelo de lenguaje completo, sino de un conjunto de pesos de ajuste fino (fine-tuning) pensado para cargarse sobre un modelo base de generación de vídeo. Según la model card, el modelo del que deriva es WAN2.2, un modelo de difusión para vídeo, y el adaptador se distribuye en un único archivo `safetensors` de 343 MiB dentro de un repositorio de 0,4 GB.

El propósito declarado del adaptador es modificar el comportamiento del modelo base para producir un efecto visual concreto en la generación de vídeo (la model card lo describe de forma muy escueta con la palabra "Shake"). El adaptador está etiquetado para ComfyUI y para la propia plataforma RunningHub, lo que indica que su flujo de uso previsto es la inferencia en nodos de ComfyUI o mediante la API y los servicios en la nube de RunningHub, más que su integración en pipelines de texto.

La relevancia de esta ficha es limitada desde el punto de vista de la evaluación de modelos de IA generativa de propósito general: se trata de un artefacto de ajuste fino muy específico, con documentación mínima, sin métricas publicadas y con una licencia no declarada de forma explícita. Resulta útil, sin embargo, como ejemplo del ecosistema de LoRAs de vídeo que se distribuyen a través de plataformas como RunningHub y de las precauciones que conviene tomar antes de reutilizarlos en producción.

## Arquitectura y entrenamiento

El artefacto es un adaptador LoRA, es decir, un conjunto de matrices de bajo rango que se inyectan en las capas del modelo base para modificar su comportamiento sin reentrenar todos los pesos. El modelo base declarado es WAN2.2, un modelo de generación de vídeo por difusión, por lo que la arquitectura efectiva de generación corresponde a la del modelo base y no a la del adaptador. No se documenta sobre qué capas se aplica el LoRA, qué rango utiliza ni qué módulos (atención, proyecciones, capas de texto) se ven afectados.

No hay información sobre el conjunto de datos de entrenamiento, el número de pasos, la resolución o la duración de los clips usados, ni sobre si se aplicaron técnicas de regularización o de aumento de datos. Tampoco se documenta ningún proceso de alineación (RLHF, DPO) ni innovación técnica asociada al adaptador. La model card se limita a indicar el nombre del archivo, el tamaño y el modelo de origen, y remite a la plataforma RunningHub para el entrenamiento y la ejecución.

## Casos de uso

- Generación de vídeo con efecto de vibración o sacudida en ComfyUI: el adaptador se cargaría como nodo LoRA junto al modelo base WAN2.2 para aplicar el efecto durante la inferencia, siempre que el flujo de trabajo del usuario ya tenga integrado el modelo base.
- Pruebas de concepto en la plataforma RunningHub: el adaptador puede ejecutarse directamente en los servicios en la nube de RunningHub sin necesidad de infraestructura propia, lo que facilita evaluar el efecto antes de integrarlo en un pipeline.
- Prototipado de animaciones cortas para redes sociales: útil para generar clips con un movimiento característico de forma rápida, aunque la falta de documentación sobre parámetros de inferencia obliga a experimentar con la escala del LoRA.
- Investigación sobre adaptadores de bajo rango en modelos de vídeo: sirve como ejemplo práctico de cómo un LoRA de 343 MiB modifica un modelo de difusión de vídeo, para estudiar el impacto del rango y de la escala en el resultado final.
- Integración en flujos de trabajo de estudio creativo: un equipo de diseño podría combinarlo con otros LoRAs y con el modelo base para explorar variantes visuales antes de fijar una dirección artística.
- Automatización mediante la API de RunningHub: para generar lotes de clips con el efecto aplicado dentro de un pipeline de producción, siempre que se respeten las condiciones de uso de la plataforma y del autor.
