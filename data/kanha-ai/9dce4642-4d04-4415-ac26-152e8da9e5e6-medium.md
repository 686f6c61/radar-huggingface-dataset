# Kanha-AI/9dce4642-4d04-4415-ac26-152e8da9e5e6-medium

## Resumen

Kanha medium es un checkpoint de chat fine-tuneado por Kanha a partir de LiquidAI/LFM2.5-1.2B-Instruct, empaquetado en formato MLC-LLM para ejecutarse íntegramente en el navegador mediante WebGPU. No es un modelo de propósito general: el propio autor indica que está entrenado para responder preguntas sobre el contenido de un sitio web concreto, de modo que su utilidad está acotada al dominio de los datos con los que se generó el conjunto de entrenamiento. El repositorio ocupa 0,7 GB, coherente con una cuantización de 4 bits sobre un modelo de aproximadamente 1.200 millones de parámetros.

El modelo se distribuye como artefacto listo para consumir desde el SDK de Kanha (paquete npm `kanha-ai`), que ofrece un widget HTML (`<kanha-bot>`) y un componente React (`<KanhaBot>`). La propuesta de valor es la inferencia en el dispositivo: no hay llamadas a API de servidor, no hay coste por consulta y las preguntas del usuario no salen del navegador. La librería MLC asociada se publica por separado en el repositorio `Kanha-AI/kanha-liquid-lfm2.5-1.2b-instruct-sft-v1-MLC`, con el binario `kanha-liquid-lfm2.5-1.2b-tuned-q4f16_1.wasm`.

La relevancia actual del checkpoint es limitada y conviene ser explícito: el repositorio acumula 0 descargas y 0 likes en el momento de redactar esta ficha, no incluye resultados de benchmarks y no documenta composición del dataset, número de tokens de entrenamiento ni idiomas soportados. Su interés es principalmente como ejemplo de despliegue de un SLM en navegador con WebGPU y como plantilla de la cadena de herramientas de Kanha (rastreo del sitio, generación de datos, fine-tuning y compilación MLC).

## Arquitectura y entrenamiento

La model card no describe la arquitectura interna ni el proceso de entrenamiento. Lo unico verificable es que se parte de `LiquidAI/LFM2.5-1.2B-Instruct` y que el resultado es un fine-tuning (etiqueta `fine-tuned`) orientado a preguntas y respuestas sobre un sitio web concreto. Kanha describe su flujo de trabajo como un pipeline de tres etapas: rastreo del sitio, generacion automatica de datos de entrenamiento y ajuste fino de un modelo compacto, seguido de la compilacion a MLC para su ejecucion en navegador. No se publican el numero de tokens de entrenamiento, la composicion del dataset, la mezcla de idiomas ni si se aplicaron tecnicas de alineacion como RLHF o DPO.

El unico detalle tecnico de despliegue confirmado es la cuantizacion `q4f16_1` (pesos de 4 bits con activaciones y acumulacion en fp16), un esquema habitual en el ecosistema MLC/WebLLM para reducir el uso de memoria en GPU. La libreria compilada se publica como modulo WebAssembly en un repositorio separado, lo que implica que el modelo no se puede cargar con runtimes que esperen safetensors o GGUF.

## Casos de uso

- Asistente de soporte embebido en un sitio web corporativo: el modelo se integra con el widget de Kanha y responde consultas sobre productos, precios o documentacion usando el conocimiento inyectado durante el fine-tuning, sin necesidad de desplegar infraestructura de inferencia.
- Documentacion tecnica interactiva: en lugar de un buscador estatico, el visitante formula preguntas en lenguaje natural sobre guias y manuales, y la respuesta se genera en su propio equipo.
- Atencion al cliente con requisitos de privacidad: al no salir los datos del dispositivo, encaja en escenarios donde las consultas contienen informacion personal o sujeta a normativa de proteccion de datos y no se quiere enviar a una API de terceros.
- Eliminacion del coste por consulta en sitios con trafico alto: el modelo sustituye a una API de pago en el caso de uso de FAQ y orientacion, con coste marginal nulo por interaccion tras la descarga inicial de los pesos.
- Aplicaciones web progresivas y entornos con conectividad limitada: una vez cacheado el artefacto, el asistente funciona sin conexion al backend de inferencia, lo que resulta util en ferias, demos y entornos de red restringida.
- Presales y cualificacion de leads en la propia pagina: el bot responde dudas frecuentes y recoge contexto del visitante sin exponer la conversacion a un servidor.
- Despliegue interno en portales de empleados: asistente de consultas sobre politicas o procedimientos internos, con el contenido confinado al navegador del empleado.
- Base para evaluar la cadena de herramientas de Kanha: sirve como referencia tecnica para equipos que quieran replicar el pipeline de rastreo, generacion de datos y compilacion MLC con su propio contenido.

## Limitaciones y advertencias

- Modelo no generalista: el autor declara explicitamente que no es de proposito general y que solo esta entrenado para responder sobre el contenido de un sitio web concreto. Fuera de ese dominio la calidad esperada es baja.
- Riesgo de alucinacion: no hay evaluaciones publicadas de fidelidad ni de tasa de invencion de respuestas. En un modelo de ~1,2 B ajustado sobre un corpus acotado, el riesgo de respuestas plausibles pero incorrectas sobre el propio dominio debe considerarse alto y requiere verificacion humana.
- Sesgos conocidos: no disponibles. No se documenta composicion del dataset ni proceso de filtrado, por lo que no es posible auditar sesgos de contenido.
- Idiomas: no disponibles en los metadatos; no se puede asumir cobertura multilingue.
- Contexto: no disponible. Se desconoce la ventana maxima admisible, lo que impide planificar conversaciones largas o inyeccion de contexto extensa.
- Licencia: lfm1.0 (Liquid AI Foundation Model License), etiquetada como `other` en HuggingFace. Es una licencia propia del modelo base y no una licencia open source estandar; antes de cualquier uso comercial es imprescindible revisar sus terminos (el enlace `LICENSE` del repositorio), ya que puede incluir restricciones de uso, requisitos de atribucion o condiciones especificas para entidades por encima de cierto umbral de ingresos.
- Dependencia del runtime: al publicarse solo como artefacto MLC compilado, el modelo queda ligado al ecosistema MLC/WebLLM y al soporte de WebGPU del navegador del usuario. No hay ruta de despliegue alternativa con los ficheros publicados.
- Madurez: 0 descargas y 0 likes, sin fecha de validacion posterior a la creacion. No debe considerarse un artefacto validado por la comunidad.
- Idoneidad en produccion: al ser un fine-tuning de sitio unico generado de forma automatica, conviene auditar las respuestas antes de exponerlo al publico y establecer un mecanismo de fallback (por ejemplo, derivacion a soporte humano) cuando la confianza sea baja.
