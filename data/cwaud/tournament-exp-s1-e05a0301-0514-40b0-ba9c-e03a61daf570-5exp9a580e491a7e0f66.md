## Resumen

El modelo `cwaud/tournament-exp-s1-e05a0301-0514-40b0-ba9c-e03a61daf570-5Exp9a580e491a7e0f66` es un adaptador LoRA entrenado con DPO (Direct Preference Optimization) mediante la librería PEFT 0.19.1 y el stack TRL, publicado por el usuario `cwaud` sobre el modelo base `unsloth/OpenHermes-2.5-Mistral-7B`. No es un modelo completo: se trata de un conjunto de pesos diferenciales que requieren cargar el modelo base para poder ejecutar inferencia. La librería declarada es `peft` y la tarea asignada es `text-generation`, con etiquetas que confirman el uso de `dpo`, `lora`, `transformers`, `trl` y un dominio conversacional.

El modelo base es un ajuste de Mistral 7B, un transformer decoder-only de aproximadamente 7,24 mil millones de parámetros, con atención de consultas agrupadas (GQA), atención de ventana deslizante y activación SwiGLU. La relevancia de este artefacto es fundamentalmente experimental: el nombre del repositorio sugiere un checkpoint intermedio generado de forma automatizada dentro de una tanda de experimentos comparativos, no una versión final destinada a producción.

La model card publicada es la plantilla vacía por defecto de HuggingFace, sin descripción, sin datos de entrenamiento, sin hiperparámetros, sin resultados de evaluación y sin licencia declarada. El repositorio registra 0 descargas y 0 me gusta, por lo que no existe validación alguna por parte de la comunidad. Cualquier uso en producción exigiría una evaluación propia previa.

## Arquitectura y entrenamiento

El artefacto es un adaptador LoRA: las matrices de pesos del modelo base permanecen congeladas y solo se entrenan matrices de bajo rango (A y B) insertadas en determinadas capas lineales, lo que reduce de forma drástica el número de parámetros entrenables y el coste de memoria del ajuste. La optimización se realiza con DPO, un método que reformula el objetivo de RLHF como un problema de clasificación sobre pares de respuestas preferidas y rechazadas, eliminando la necesidad de entrenar un modelo de recompensa explícito y de muestrear durante el entrenamiento. Las etiquetas del repositorio confirman el uso del entrenador DPO de TRL y de la librería PEFT en su versión 0.19.1.

No se dispone de información sobre el número de tokens de entrenamiento, la composición del dataset de preferencias, el rango y el alfa del adaptador, los módulos objetivo, la tasa de aprendizaje, el número de épocas ni la precisión usada (fp16, bf16 o fp8). El modelo base, `unsloth/OpenHermes-2.5-Mistral-7B`, es a su vez un ajuste de Mistral 7B sobre el corpus OpenHermes 2.5, orientado a diálogo e instrucciones en inglés; el adaptador hereda esa base y aplica una capa de alineación por preferencias cuyo efecto concreto no está documentado ni medido. El repositorio ocupa 1,3 GB, un tamaño superior al habitual en adaptadores LoRA para un modelo de 7B, lo que sugiere la posible inclusión de estados del optimizador, checkpoints intermedios o pesos fusionados; conviene inspeccionar el contenido antes de desplegarlo.

## Casos de uso

- Investigación en alineación por preferencias: el adaptador permite reproducir y comparar el efecto de una pasada DPO sobre una base instruct concreta, con un coste de almacenamiento reducido frente a un ajuste completo de los 7B parámetros.
- Servicio multi-adaptador con vLLM: al ser un LoRA sobre Mistral 7B, varias adaptaciones pueden servirse sobre una única instancia del modelo base, lo que abarata el despliegue de variantes experimentales en un mismo endpoint.
- Evaluación comparativa de checkpoints: el nombre del repositorio indica que forma parte de una tanda de experimentos; resulta adecuado como material de partida para analizar la varianza entre ejecuciones de un mismo pipeline de DPO.
- Generación de diálogo en inglés para prototipos: con la cautela de que no hay evaluación, puede usarse para pruebas internas de asistentes conversacionales donde el coste de un error sea bajo.
- Ajuste posterior específico de dominio: el adaptador puede servir como punto de partida para un nuevo LoRA sobre un corpus sectorial, aprovechando que los pesos base quedan intactos.
- Docencia y formación técnica: sirve para ilustrar de forma práctica cómo se aplica DPO con TRL y PEFT sobre un modelo de 7B en hardware de gama alta de consumo.
- Red-teaming y análisis de sesgos: útil como sujeto de pruebas para medir cómo una tanda DPO no documentada altera el comportamiento de la base en términos de toxicidad o sesgo.

## Requisitos de hardware

- Tamaño del artefacto: 1,3 GB en el repositorio (adaptador o checkpoints; verificar contenido).
- Inferencia en fp16/bf16: requiere cargar el modelo base completo, aproximadamente 14,5 GB de pesos más la caché KV. Estimación: 16-20 GB de VRAM para contextos moderados.
- Inferencia en 8 bits: estimación de 9-11 GB de VRAM.
- Inferencia en 4 bits (bitsandbytes NF4 o GGUF Q4_K_M): estimación de 5-6 GB de VRAM.
- GPU recomendadas: A100 40/80 GB, H100, L40S o A10G para servicio concurrente; RTX 4090 (24 GB) o RTX 3090 (24 GB) para fp16 en uso individual.
- GPU de consumo: sí, cabe en RTX 3060 12 GB, RTX 4060 Ti 16 GB, RTX 4070 y superiores siempre que se aplique cuantización de 4 u 8 bits. En 24 GB se puede ejecutar sin cuantizar.
- Opciones de despliegue: `transformers` + `peft` (referencia obligada para cargar el adaptador), vLLM con soporte LoRA, TGI, y llama.cpp u Ollama mediante conversión del modelo base a GGUF y aplicación del adaptador.
- Entrenamiento DPO: un LoRA sobre 7B en bf16 requiere del orden de 16-24 GB de VRAM según rango y longitud de secuencia; con QLoRA de 4 bits puede bajar a 10-12 GB. Son estimaciones generales para este tamaño, no medidas publicadas para este repositorio.
