# alexkstern/code_5pct_separate_1e18_s0_2026-08-16_18-53-50_285290-pt

## Resumen

El modelo `alexkstern/code_5pct_separate_1e18_s0_2026-08-16_18-53-50_285290-pt` es un checkpoint de entrenamiento generado con el framework [nanochat](https://github.com/karpathy/nanochat), una implementación ligera y eficiente de entrenamiento de transformers. Se trata de un modelo de lenguaje de tamaño reducido (12 capas, 768 dimensiones de embedding, vocabulario de 65 536 tokens) entrenado con una estrategia de dos fases: primero pre-entrenamiento sobre 20 000 millones de tokens de FineWeb (texto general) y después una fase de post-pre-training sobre 1 000 millones de tokens de código de GitHub, con una proporción del 5 % de tokens de código en la mezcla final. El objetivo computacional era alcanzar 1e18 FLOPs, y el checkpoint se guardó en el paso 3368.

Este modelo es relevante para la comunidad de investigación porque explora la eficiencia del entrenamiento con mezclas de datos heterogéneos (texto y código) en modelos pequeños, y sirve como base para estudiar el impacto de la proporción de datos de código en las capacidades finales. No es un modelo listo para producción: es un artefacto experimental sin fine-tuning instructivo ni alineación, orientado a análisis y reproducción de experimentos.

## Arquitectura y entrenamiento

El modelo sigue una arquitectura transformer decoder-only estándar, con atención multi-cabeza (6 cabezas) y 12 capas. El vocabulario se fija en 65 536 tokens mediante un tokenizer BPE de nanochat. La configuración de entrenamiento incluye dos fases: pre-training (PT) sobre el dataset `fineweb-nanochatbpe-20B` (20 000 millones de tokens de FineWeb) y post-pre-training (PPT) sobre `github-code-nanochatbpe-1B` (1 000 millones de tokens de código de GitHub). La proporción de tokens de código en la mezcla es del 5 % (`alpha_ppt=0.05`), con una transición que reinicia el optimizador pero no re-inicializa los embeddings. El learning rate sigue una forma trapezoidal sin warmup y con warmdown del 40 % del entrenamiento, con tasas separadas para matrices (0.03), embeddings (0.3) y unembeddings (0.004). El entrenamiento se realizó en una GPU con pico de 2250 TFLOPS (probablemente H100), usando compilación del modelo y gradiente clipping.
