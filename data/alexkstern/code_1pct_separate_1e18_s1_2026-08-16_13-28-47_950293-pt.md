# alexkstern/code_1pct_separate_1e18_s1_2026-08-16_13-28-47_950293-pt

## Resumen

Este modelo es un checkpoint experimental de entrenamiento generado con [nanochat](https://github.com/karpathy/nanochat), un framework ligero de entrenamiento de modelos GPT desarrollado por Andrej Karpathy. El checkpoint corresponde al paso 3.735 de un experimento denominado `code_1pct_separate_1e18_s1`, cuyo objetivo es estudiar el efecto de un entrenamiento separado (pre-entrenamiento y post-entrenamiento) con una proporción del 1% de datos de código. El modelo tiene una arquitectura transformer decoder pequeña (11 capas, 768 de dimensión, 6 cabezas de atención) y un vocabulario de 65.536 tokens, con una ventana de contexto de 2.048 tokens. Está pensado como un banco de pruebas para investigar técnicas de entrenamiento eficiente, no como un modelo listo para producción.

La relevancia actual radica en su uso como referencia para estudiar la transferencia de conocimiento entre dominios (texto general y código) con un presupuesto de cómputo fijo (1e18 FLOPs). El autor lo publica bajo licencia Apache 2.0, lo que permite su uso y modificación sin restricciones comerciales. No se han publicado evaluaciones de rendimiento ni descripciones de capacidades más allá de los datos de entrenamiento.

## Arquitectura y entrenamiento

El modelo sigue la arquitectura estándar de un transformer decoder (similar a GPT-2) con 11 capas, 6 cabezas de atención y dimensión de embedding 768. El vocabulario es de 65.536 tokens, generado con un tokenizer BPE específico de nanochat (`nanochatbpe`). No se especifican innovaciones arquitectónicas adicionales; se trata de un diseño clásico.

El entrenamiento se divide en dos fases: una fase de pre-entrenamiento (pt) sobre el dataset `fineweb-nanochatbpe-20B` (20 mil millones de tokens de texto general) y una fase de post-entrenamiento (ppt) sobre `github-code-nanochatbpe-1B` (1 mil millones de tokens de código de GitHub). La proporción de tokens de código es del 1% del total (alpha_ppt=0.01). El entrenamiento se realiza con una política de tasa de aprendizaje trapezoidal, sin calentamiento, con un descenso del 40% del total de pasos y una tasa final de 0.0. Se emplean tasas de aprendizaje diferenciadas para matrices (0.03), embeddings (0.3) y unembeddings (0.004). El optimizador no usa weight decay. Se utilizó compilación de modelo (`compile_model: true`) y el total de FLOPs objetivo es 1e18, alcanzando 9.9e17 FLOPs reales. El entrenamiento duró 415.5 segundos en un hardware con pico de 2250 TFLOPS (probablemente una GPU de alta gama, aunque no se especifica).
