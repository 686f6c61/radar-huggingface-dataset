An open, versioned dataset about the models published on Hugging Face:
normalized metadata, classified licenses, a daily time series of likes and
downloads, the models that disappear from the hub, the ones that get renamed,
and a technical card for every model in Spanish (and in English for a growing
part of the catalog).

It is generated by **[HF//RADAR](https://radar-huggingface.686f6c61.dev)**, a
radar that tracks the hub and writes a card for each model it indexes. This
repository is its data output and is updated three times a day.

**If you find it useful, a star on GitHub helps others discover it.**

**Not every model has an open license.** Each one has its license classified
in `license_family`; if you only want the open ones, filter by
`license_family = "oss"`.

## What it is for

The Hugging Face API tells you how a model is doing today. This dataset lets
you ask other questions:

- **What gets published and by whom**: organizations, licenses, sizes, tasks
  and formats (GGUF, MLX, safetensors, ONNX, diffusers).
- **What gains traction**: the `metrics` table keeps likes, 30-day downloads
  and trending score for each model, day by day.
- **What disappears**: the hub never announces removals. Here every removed
  model stays, with its date, how long it lived and the pattern its removal
  left.
- **What gets renamed**: old id, new id and date.
- **What each model is**: a technical card in Spanish (what it does, what it
  is for, requirements, limitations).

## Four ways to use it

| Way | Where | Good for |
|---|---|---|
| **Parquet tables** | [Hugging Face](https://huggingface.co/datasets/686f6c61/radar-huggingface-dataset) and the [`latest`](https://github.com/686f6c61/radar-huggingface-dataset/releases/tag/latest) release | Analysis with pandas, DuckDB, Polars or `datasets`. Recommended |
| **One file per model** | `data/{author}/{model}.json` and `.md` | Looking up a single model or following its changes in the git history |
| **JSONL bulk** | `models.jsonl.gz` in every release | Everything in one file, with the card embedded |
| **Manifest** | `index.json` | List of all models with their key fields and the path of their file |

## What you will find in the Parquet

Six tables that join on the model's Hugging Face id (`id`, or `model_id` in
`metrics`). Every column is described in [SCHEMA.md](SCHEMA.md).

| Table | Rows | What it is |
|---|---|---|
| `models.parquet` | 130,647 | One row per model: metadata, license, size, formats, flags |
| `metrics.parquet` | 3,424,740 | Time series: likes, 30-day downloads and trending score per model and day |
| `fichas_es.parquet` | 130,647 | The technical card of each model, in Spanish (Markdown) |
| `fichas_en.parquet` | 23,544 | The English translation of the card, where available |
| `tombstones.parquet` | 10,263 | Models removed from the hub, with their lifetime and removal pattern |
| `renames.parquet` | 2,992 | Renamed repositories: old id, new id and date |

In `models` you will find, among other columns:

- **Identity**: `id`, `author`, `url`, `created_at`, `updated_at`.
- **License**: `license` (as the author declares it) and `license_family`.
- **What it is**: `pipeline_tag`, `library`, `languages`, `tags`,
  `base_model`, `formats`, `is_conversational`.
- **Size**: `parameters`, `storage_bytes`, `context_length`.
- **Usage**: `likes`, `downloads_30d`, `trending_score` (latest read).
- **Flags**: `gated`, `disabled`, `removed`, `removed_at`, `removal_pattern`,
  `renamed_to`, `renamed_at`.
- **Extras**: `benchmarks` (the ones declared in the model card), `sources`
  (web sources used when writing the card), `has_ficha_en` and `path` (path of
  that model's JSON file in this repository).

Lists (`tags`, `languages`, `formats`) are native Parquet lists, not text:
filter them with `list_contains` in DuckDB or `explode` in pandas.

```python
# pandas, from Hugging Face
import pandas as pd
models = pd.read_parquet("hf://datasets/686f6c61/radar-huggingface-dataset/models.parquet")
metrics = pd.read_parquet("hf://datasets/686f6c61/radar-huggingface-dataset/metrics.parquet")
```

```python
# datasets
from datasets import load_dataset
models = load_dataset("686f6c61/radar-huggingface-dataset", "models", split="train")
```

```sql
-- DuckDB: the GGUF models that gained the most downloads in the last 7 days
SELECT m.id, max(x.downloads_30d) - min(x.downloads_30d) AS gained
FROM 'hf://datasets/686f6c61/radar-huggingface-dataset/metrics.parquet' x
JOIN 'hf://datasets/686f6c61/radar-huggingface-dataset/models.parquet' m ON m.id = x.model_id
WHERE x.ts >= now() - INTERVAL 7 DAY AND list_contains(m.formats, 'gguf')
GROUP BY 1 ORDER BY gained DESC LIMIT 20;
```

```sql
-- DuckDB: how long removed models lived, by removal pattern
SELECT removal_pattern, count(*) AS models, median(lifetime_days) AS days
FROM 'https://github.com/686f6c61/radar-huggingface-dataset/releases/download/latest/tombstones.parquet'
GROUP BY 1 ORDER BY models DESC;
```

`manifest.json` ships with the tables and gives the export date, row count,
size and SHA-256 of each one, so a download can be verified.

## One file per model: `data/`

One folder per author and, inside, two files per model: the `.json` with the
metadata and the `.md` with the card.

```
data/
├── qwen/
│   ├── qwen3-8-27b.json          # metadata (SCHEMA.md)
│   ├── qwen3-8-27b.md            # technical card, in Spanish
│   ├── qwen3-8-27b-fp8.json
│   └── qwen3-8-27b-fp8.md
├── sentence-transformers/
│   ├── all-minilm-l6-v2.json
│   └── all-minilm-l6-v2.md
└── ... (thousands of authors)
```

- The path comes from the model's `slug`: lowercase, with dots and other
  symbols turned into hyphens (`Qwen/Qwen3.8-27B` lives at
  `data/qwen/qwen3-8-27b.json`). You do not need to derive it: `index.json`
  and the `path` column of `models.parquet` give the path of every model.
- If two different models end up with the same slug (re-uploads that only
  change capitalization), the newer one gets a `-2`, `-3`... suffix.
- The `.json` follows [SCHEMA.md](SCHEMA.md), version 2. Nulls are explicit:
  a key is never omitted.

```bash
# A single model
curl -s https://raw.githubusercontent.com/686f6c61/radar-huggingface-dataset/main/data/qwen/qwen3-8-27b.json
```

```python
# The whole dataset with the card embedded (JSONL bulk)
import pandas as pd
url = "https://github.com/686f6c61/radar-huggingface-dataset/releases/download/latest/models.jsonl.gz"
df = pd.read_json(url, lines=True)
```

## Where each piece of data comes from

- **Which models get in.** The radar reads the hub's trending, recently
  created and recently updated lists and indexes what shows up there. It
  started in August 2026. It is not a mirror of the hub: a model that never
  appeared in those lists is not here.
- **Metadata.** From the Hugging Face API. Free-text fields of model cards
  (license, library, task, base model) are sanitized on the way in.
- **License.** `license` is what the author declares; `license_family` is our
  own classification into three groups.
- **Parameters and context.** `parameters` is the count the hub computes from
  safetensors or GGUF files; `context_length` comes from GGUF metadata. If
  the hub does not compute them, they are `null`.
- **Metrics.** A daily pass, around 02:00 UTC, reads likes and downloads for
  each model. Models with real usage (50 or more downloads, 2 or more likes,
  or created in the last 21 days) are read every day; the rest, roughly once
  a week. So the number of points per model varies (median 27, maximum 61 on
  14 November 2026).
- **Removed models.** A model is flagged as removed when the hub returns a
  real 404. `removed_at` is the date of the pass that found it gone, not the
  real one.
- **Removal pattern.** The hub does not publish reasons. `removal_pattern` is
  the pattern the data shows, not a confirmed cause (see
  [SCHEMA.md](SCHEMA.md)).
- **Renames.** The hub redirects the old id to the new one and the daily pass
  records it. The old id keeps its file, with `renamed_to`.
- **Cards.** Written by a language model from the model card and web sources
  (`sources`). The English ones are machine translations of the Spanish ones
  and are only published while they match the current card.
- **Benchmarks.** The ones the author declares in the card's `model-index`.
  An empty list means none were declared, not that none exist.

## Limits worth knowing

- `downloads_30d` is already a 30-day rolling window, as the hub reports it.
  The difference between two days of the series is the difference of that
  window, not one day of downloads.
- The metrics series starts on 15 September 2026. Before that date there are
  only full snapshots of the dataset in the releases.
- `base_model` is kept as the author wrote it and may name several models.
- Cards can contain errors: check the original model card before using a
  model in production.
- Ids that look like credentials are not published, and anything that looks
  like a token inside the data is replaced by `[REDACTED]`.

## How it is updated

A worker on the radar's server runs three times a day, at 06:00, 14:00 and
22:00 (Europe/Madrid time):

1. It exports the per-model files and the Parquet tables from the radar's
   database.
2. It uploads the Parquet tables to Hugging Face.
3. It commits to this repository only what changed
   (`data: +new ~modified -deleted`) and pushes.
4. CI validates the dataset, builds the bulk, attaches the Parquet tables to
   the `latest` release and creates the numbered release for that run.

A model's files are rewritten in place: the tree always reflects the most
recent state. The previous value stays in the git history, in the numbered
releases and, for likes and downloads, in `metrics.parquet`.

Removed models are not deleted: they stay with `removed: true`. A file is
only deleted if the model is removed from the radar's database.

## Versioning

One release per run with new data, with the time slot in the version:

| Run (Europe/Madrid) | Slot | Bump | Example |
|---|---|---|---|
| 06:00 | Morning | major | `v3.0.0` |
| 14:00 | Afternoon | minor | `v3.1.0` |
| 22:00 | Night | patch | `v3.1.1` |

`v14.2.1` is the export of the night of day 14 since the dataset started.
Numbered releases never change: to reproduce an analysis, pin a specific
version. Format changes are announced by bumping `schema` and logged in
[CHANGELOG.md](CHANGELOG.md).

- **`latest` release**: always points to the most recent export and the URLs
  of its files never change. It is the right one for recurring consumption.
  It carries the bulk and the Parquet tables.
- **Numbered releases**: carry the `models.jsonl.gz` bulk of that run.

## Checks

Every push goes through CI: valid JSON conforming to the schema, every
`.json` with its `.md`, `index.json` consistent with the tree and
documentation present. Every 6 hours CI also fails if the dataset has gone
more than 20 hours without being published. The schema of the per-model files
is also available as JSON Schema in
[`schema/model.schema.json`](schema/model.schema.json).
